## 시험 세트

평가 자료는 모두 `api/eval/data/`(Git 제외) 한곳에 있다.

| 경로 | 내용 |
|---|---|
| `store-a`~`store-d` | 평가 매장(영상·음성·스캔·카톡) |
| `store-e` | 문서 전용 매장(docx 7개, 2026-11-06 추가). 정답지는 **초안** |
| `추출결과/` | 외부 모델 실행 결과·관찰(Phase 0) 폴더 (옛 저장소 루트 `추출결과/`) |
| `single-call-set/` | 이 시험 세트(아래 스크립트가 만든다) |

만드는 법:

    cd api && python scripts/build_single_call_set.py --stores eval/data --out eval/data/single-call-set

| 출처 | 사례 | 형식 | 정답 |
|---|---|---|---|
| store-a~d | 스캔(레시피북·원재료·공지) 9 · 카톡 4 · 음성 4 | `DOC_IMAGE` `CHAT` `AUDIO_TRANSCRIPT` | 기존 정답지(`truth/facts.json`)를 자료별로 뗌, `owner_confirmed: "TEST"` |
| store-e | docx 7 (마감 절차·재고·응대·청소·체크리스트·위생·근무표) | `DOC_TEXT` | **초안**(`owner_confirmed: false`) — 검수 후 `"TEST"` 로 바꾸기 전에는 채점하지 않는다. 검수 도우미 `store-e/REVIEW_TRUTH.md` |
| 합성 사장님 글 | 8 (`owner_texts.json`) | `OWNER_TEXT` | 글쓴이가 정답을 안다, `"TEST"` |

사례 폴더마다 `meta.json`(형식·주된 로직·입력 상태), `gold.json`(정답 사실), 입력 파일이 있다.
`index.json` 의 `gold_status` 가 `SCORABLE` 인 사례만 채점한다. 영상 자료는 넣지 않는다.

### 남은 준비
- **음성 4건 전사:** 입력은 실제 녹음의 whisper 전사본이다(`input_status: PENDING_TRANSCRIPT`). 대본(`SCRIPT.md`)을 입력으로 쓰면 음성 손실이 실제보다 좋게 나오므로 쓰지 않는다. 전사는 유료라 승인 뒤 한 번 만들어 `transcript.txt` 로 둔다(세트를 다시 만들어도 보존된다).
- **store-e 정답 초안 검수:** 142개.
- **store-a 메뉴명 치환:** 원본 자료의 메뉴명과 정답지 메뉴명이 다르다(`MENU_MAP.json`, Git 제외). 채점 때 치환한다.
- store-e 는 영상·음성·스캔·카톡이 없어 `check_eval_data.py` 의 4유형 규칙을 통과하지 않는다(문서 전용 매장).

## 한계
- 정답지는 전부 팀 판정(`TEST`)이다. 실제 점주 확인이 아니다 — "우리가 정답이라고 본 것 대비" 수치다.
- a~e 를 모두 개발에 쓰므로 처음 보는 매장에서의 수치가 아니다.
- 합성 사장님 글은 우리가 쓴 글이라 실제 사장님 글보다 깔끔할 수 있다.
