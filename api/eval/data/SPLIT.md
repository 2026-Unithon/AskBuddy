# 평가 매장 분할 (dev / holdout)

> **이 파일은 커밋한다. 자료 수집 전에 정하고, 이후 바꾸지 않는다.**
> 나중에 분할을 바꾸면 holdout 이 holdout 이 아니게 된다. 그건 부정행위다.

## 원칙

- **dev** — 프롬프트·임계값을 여기서 고친다. 몇 번이고 본다.
- **holdout** — 봉인한다. 개선이 끝난 뒤 **한 번만** 돌린다.
  한 번 들여다보면 그 순간 개발셋이 되고, 되돌릴 수 없다.

holdout 이 있어야 **"튜닝에 쓰지 않은 매장에서 N%"** 를 말할 수 있다.
dev 만으로 낸 수치는 그 매장들에만 해당하고, 처음 보는 매장에서 몇 %인지 말하지 못한다.

## 분할

| slug | 구분 | 상태 | 확정일 |
|---|---|---|---|
| `eval-a` | **dev** | 자료·사실 정답지 확보 | 2026-09-14 |
| `eval-b` | **dev** | 자료·사실 정답지 확보 | 2026-09-14 |
| `eval-c` | ~~holdout~~ → dev | 자료·사실 정답지 확보 · 봉인 해제(2026-11-06, 아래 기록) | 2026-09-14 |
| `eval-d` | ~~holdout~~ → dev | 자료·사실 정답지 확보 · 봉인 해제(2026-11-06, 아래 기록) | 2026-09-14 |
| `eval-e` | **dev** | 문서(docx) 7개 · 사실 정답지 **초안**(검수 전) | 2026-11-06 |
| `eval-f` | **holdout** | 미수집 (추후 추가) | — |
| `eval-g` | **holdout** | 미수집 (추후 추가) | — |

현재 dev 2 / holdout 2 로 시작한다. `e`·`f` 는 나중에 추가하며 **holdout 으로 고정**이다.
**2026-11-06 변경(사용자 결정):** 관찰 문서 카페를 `eval-e` 로 넣어 dev 로 쓰고, holdout 예약 자리를 `f`·`g` 로 옮겼다. `f`·`g` 는 **holdout 으로 고정**이다.
나중에 추가되는 매장을 dev 로 돌리면 holdout 비율이 줄어 일반화 주장이 약해진다.

`demo-cafe` 는 데모·시연 전용이며 평가에 쓰지 않는다. 가상 매장이다.

## 규칙

- 매장 식별자는 **익명 slug 뿐이다.** 브랜드명·상호를 이 파일에도, `manifest.json` 에도,
  DB `store_name` 에도, 커밋 메시지에도 쓰지 않는다.
- 새 매장을 수집하면 위 표의 `상태` 와 `확정일` 만 갱신한다. **구분은 바꾸지 않는다.**
- holdout 실행은 `run_eval.py` 에서 명시적 플래그를 요구한다. 실수로 돌지 않게 한다.
- holdout 을 연 날짜와 그때의 코드·프롬프트 버전을 아래에 기록한다.

## holdout 개봉 기록

| 날짜 | 매장 | run_id | 코드 버전 | 비고 |
|---|---|---|---|---|
| 2026-11-06 | `eval-c`·`eval-d` | — (실행 전) | 브랜치 `w/extract-single-call-eval` | **사용자 결정으로 봉인 해제.** 한 번 호출 추출 시험(`api/eval/single_call/`)에 처음부터 개발용으로 쓴다 |

**2026-11-06 부터 `eval-c`·`eval-d` 는 holdout 이 아니다.** 위 결정과 `eval-e` 추가로 a~e 다섯 매장이 모두 개발용이다.
이 매장들에서 낸 수치는 "튜닝에 쓴 매장 대비" 이며 처음 보는 매장에서의 수치가 아니다.
일반화를 말하려면 아직 수집하지 않은 `eval-f`·`eval-g`(holdout 고정)가 필요하다.
