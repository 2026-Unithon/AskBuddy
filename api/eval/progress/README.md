# 품질 추이 기록

**여기가 "처음보다 얼마나 좋아졌는가" 를 보는 곳이다.**
발표·지원서에서 개선 이력을 보여줄 때 이 폴더를 쓴다.

| 파일 | 내용 |
|---|---|
| `PROGRESS.md` | 자동 생성 요약. 처음 대비 현재, 전체 추이, 설정 이력 |
| `metrics.jsonl` | 실행 1건 = 1줄. append-only. 기존 줄을 고치지 않는다 |

## 갱신

```bash
cd api && python scripts/track_progress.py
```

DB(`evaluation_runs`)에서 종료된 실행을 읽어 `metrics.jsonl` 에 없는 것만 덧붙이고
`PROGRESS.md` 를 다시 만든다. **기존 기록을 덮어쓰지 않는다.**

## 왜 커밋하는가

숫자 이력이 Git 에 남아야 "언제 무엇을 바꿔서 얼마나 올랐는지" 를 나중에 증명할 수 있다.
집계 숫자만 담고 **질문문·카드 본문·매장 자료·브랜드명은 담지 않는다.**

실행 1회짜리 상세 리포트(`eval/reports/`)는 질문·답변 원문이 들어가므로 Git 제외다.

## 정본은 DB다

이 폴더는 사본이다. `PROGRESS.md` 를 손으로 고치지 않는다.
지표 정의를 바꾸려면 `app/team/metrics.py` 를 고치고, 그러면
**그 전 실행과는 비교가 성립하지 않는다는 점**을 기록에 남긴다.

## 읽을 때 주의

- **통과율만 보지 않는다.** 근거 없는 답변은 목표 0이다. 하나라도 있으면 통과율이 높아도 실패다.
- **문항 수가 다른 실행끼리 비교하지 않는다.** 같은 골든셋에서만 전후 비교가 성립한다.
- **코드·프롬프트 버전이 같은데 수치가 움직였다면** 자료나 카드가 바뀐 것이다.
