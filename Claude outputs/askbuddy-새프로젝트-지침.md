# AskBuddy — 프로젝트 지침

카페 등 소규모 매장의 업무 인수인계를 AI가 대신하는 서비스. 2026 유니톤 팀 프로젝트.
이 프로젝트는 **최신 상태만 다룬다.** 예선·본선 준비 시기의 기록은 옮겨오지 않았고, 옛 대화 요약을 근거로 답하지 않는다.

## 정본 순서 (충돌하면 위가 이긴다)

1. **팀 노션** — 제품 범위, 일정, 팀 결정, 역할. 연결된 커넥터로 직접 읽는다
2. **로컬 리포 `~/new/New_Source/2026unithon`** — 기술 사실의 최종 근거. 코드와 `supabase/migrations/`가 말하는 것이 사실이다
3. **`docs/ASKBUDDY_MVP_CONTRACT_V1.md`** — 데이터·API 계약. 상태값·엔드포인트·폐기 규칙
4. `docs/AskBuddy_설계최종본_v5.md` — 제품 설계

`docs/AskBuddy_개발가이드.md`, `docs/ingest-contract.md`, 사업계획서·발표키트 PDF는 **배경 자료**다. 계약 v1 이전 내용이라 그대로 인용하지 않는다.

## 답하기 전에 할 것

- **제품·일정·팀 질문** → 노션을 먼저 검색한다. 기억이나 이전 요약으로 답하지 않는다
- **기술 사실**(임계값, 테이블 수, 엔드포인트, 모델명, 상태값) → 노션이 아니라 **코드에서 확인**한다. `device_bash`로 grep·파일 읽기를 하고, 확인한 파일이나 커밋을 같이 밝힌다
- 코드에서 확인하지 못한 숫자는 추정하지 말고 "확인 필요"라고 말한다
- 노션과 코드가 어긋나면 어긋났다는 사실 자체를 먼저 알린다

## 현재 기준 사실 (2026-09-12, main @ `d62c08e`)

아래와 다른 내용을 보면 코드를 다시 확인한다.

- **검색 게이트 2단** — `RETRIEVAL_THRESHOLD` 0.35 하한 + `RETRIEVAL_STRONG_SCORE` 0.62 + 낱말 앵커 검사
- **답변 생성 있음** — `compose_grounded_answer()`, gemini-3.6-flash, `response_schema` 강제, temperature 0.0, 승인 카드 상위 3장만 입력
- **서버 검증 3종** — 인용 화이트리스트 / 답변 숫자 ⊆ 카드 숫자 / 답변 실질낱말 ⊆ 카드 낱말. 하나라도 실패하면 생성문 폐기 후 카드 원문(`CARD_ORIGINAL`·`FALLBACK`). `ANSWER_MODE=extractive`로 생성 차단 가능
- **DB 38 테이블** — 초기 24 + 마이그레이션 8건
- **카드** — `review_status`(PENDING/NEEDS_REVIEW/APPROVED/EXCLUDED)가 정본, 본문은 `card_versions`, `draft_version_id`와 `published_version_id` 분리
- **검색·학습은 `published_version_id` 있는 승인 카드만** 본다
- **로드맵 동적 구성** — 카테고리 + 승인 카드. 승인 카드 없으면 `stages=[]`
- **점주 답변 루프** — IDENTICAL / NEW / SUPPLEMENT / CONFLICT 관계 판정. 충돌은 자동 공개 금지
- **알림** — 앱 내부 알림이 정본, Web Push는 추가 전달
- **매장 격리** — RLS 미사용. JWT의 `store_id`를 API가 전담
- **미구현** — `/team/evaluations` 평가 하네스(테이블만 존재), 하이브리드 검색, Kiwi 형태소, `store_glossary` 앵커 확장, 핀 보드

## 지금은 틀린 문장 (예전엔 맞았음, 재사용 금지)

- "생성 모델을 안 씁니다. 답변은 카드 본문 그대로입니다" → 생성하되 서버가 검증한다
- "24 테이블" → 38
- "업로드 게이지 80% 이상에서 미리보기" → 계약 v1에서 폐기
- "검색 임계 0.5" / "D11은 0.6" → 0.35 + 0.62 + 앵커
- "정답 12/13 · 오답 0/10" → 생성 답변 붙기 전 파이프라인 수치. 하네스로 다시 재기 전엔 인용하지 않는다
- "고정 로드맵 게임판", "`is_verified` boolean으로 승인 표현" → 둘 다 대체됨

## 응답 방식

- 반말, 두괄식, 핵심만. 군더더기 부사 없이
- 숫자나 동작을 말할 때는 근거 파일·커밋을 함께 밝힌다
- 코드 수정은 리포에서 직접 한다. 파일을 컨테이너로 올렸다 내리지 않는다
- 커밋 접두사 `[input]` `[db]` `[output]` `[docs]`. 커밋·푸시는 시키기 전까지 하지 않는다
- 확실하지 않으면 아는 척하지 말고 확인하거나 모른다고 한다
