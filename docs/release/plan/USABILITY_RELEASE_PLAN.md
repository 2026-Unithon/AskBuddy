# 현재 기능 사용성 릴리스 계획

## 목표와 범위

현재 구현된 업로드→업무 카드→점주 검수/승인→직원 사용의 최소 흐름을 실제로 사용할 수 있게 한다.
장기 C0/W/R 계획은 유지하지만 기능 확장 대신 현재 흐름의 실패·대기·혼란을 우선 고친다.
현재 모든 입력 유형이 파일럿 품질을 충족했다고 가정하지 않는다. 실측 뒤 검증된 지원 범위를 정한다.
보안/승인/오답 회귀에 실패하면 화면이 빨라져도 출시하지 않는다.

## 순서와 완료 결과

| 단계 | 산출물 | 통과 확인 |
|---|---|---|
| REL-00 재현 | 동결 작은 자료·코드/설정·화면/단계별 측정 | 어디가 왜 느리고 실패하는지 재현 가능, 추정과 관측 구분 |
| REL-01 처리/대기 | 짧은 DB 작업·제한된 동시성·실제 작업 상태·복구 | 추출 중 다른 요청이 막히지 않음, 중복/실패/재시작 회복 |
| REL-02 추출 | 지원 유형별 작은 품질 수정·실패 대안 | 사실/규격/조건 보존, 누락/오조립·검수 부담·비용 비교 |
| REL-03 반응 | 요청별 피드백·좁은 갱신·상태 유지 | 버튼 반응과 실제 완료가 개선, 성공 위장/데이터 손실 없음 |
| REL-04 화면 | 기존 핵심 화면 정보/컴포넌트 정리 | 설명 없이 파일 추가→검수→승인 가능, 모바일/긴 내용 확인 |
| REL-05 파일럿 | 실제 API/DB·기기/E2E·보안·복구·배포 후보 | 필수 게이트 통과 뒤 범위를 제한해 운영 실행 요청 |

REL-03/04는 기준선 이후 병행할 수 있다. 색/여백 개선을 먼저 하더라도 P0 처리·품질 문제를 완료로 대체하지 않는다.
전체 영속 worker/불변 revision/새 검색을 재설계하는 변경은 상위 작업 ID에 연결한다.
파일럿에 필요한 최소 재시작 복구/안전 읽기 검사를 장기 과제로 미루지 않는다.

## 책임

W: 업로드/전처리/추출/작업, 카드/검수/승인/카테고리 UI와 DB 연결 수명·품질 평가.
R: 직원 질문/학습/FAQ/점주 답변/알림 UI, 읽기 인증·공개 근거·안전한 답변 경로.
공통 types/query/layout/config/schema는 변경 묶음별 한 편집자와 상대 검토로 진행한다.
이미 진행 중인 CLASSIFY/RELATION 원가 계측 변경은 보존하고 담당 변경과 충돌하지 않게 한다.

## 사용자에게 보이는 결과

- 파일별 전송과 서버 접수/처리가 분리되고 접수 뒤 다른 작업을 할 수 있다.
- 준비된 카드, 처리하지 못한 자료와 실제 다음 행동이 분명하다.
- 카드의 규격·수치·주의·근거를 비교하고 수정/승인을 혼동하지 않는다.
- 버튼 클릭 피드백은 즉시, 저장/공개 완료는 서버 성공 뒤에 표시한다.
- 실패·부분 성공·재시도·재진입에서도 입력/원본/공개본을 잃지 않는다.

이 문서 작성은 구현·실사용 테스트·배포 위임이 아니다. 다음 구현 범위는 REL-00 결과와 TODO로 좁힌다.
