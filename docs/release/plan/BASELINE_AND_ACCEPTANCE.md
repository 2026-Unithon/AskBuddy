# 릴리스 기준선과 인수

## 측정 방법

익명/합성 작은 자료와 기존 dev만 사용한다. holdout C/D는 열지 않는다.
실제 모델 실행은 호출 범위/예산을 별도로 확인하고, fake 검증을 실제 추출 품질로 보고하지 않는다.
같은 코드/설정/자료/네트워크 조건에서 전후를 비교하고 cold/warm, 최초/재사용, 성공/실패를 구분한다.
원본/화면의 개인정보·비밀값은 Git 제외 산출물에 보존하고 review에는 익명 ID와 요약만 남긴다.

| 영역 | 기록할 것 |
|---|---|
| 파일 추가 | 크기/페이지/초/파일 수, 전송/해시/등록/작업 접수 각각의 시간 |
| 추출 | 큐 대기, 다운로드/전처리/STT/모델 추출/원장/조립/저장, 실제 호출/토큰/오류/재시도 |
| 일반 버튼 | 클릭→첫 피드백, API/DB 대기, 응답→화면 반영, 기다리는 동안 다른 행동 가능 여부 |
| 카드 품질 | 원본 기대 사실, 추출 facts, 카드 보존/누락/왜곡, 근거/규격, 사람 수정 수·검수 시간 |
| 작업 복구 | 이탈/새로고침/중복/응답 유실/프로세스 종료/lease 경합의 상태·원본·카드 보존 |
| 화면 | 모바일 크기, 0/1/30+ 카드, 긴 내용/키보드, loading/error/partial/retry/승인 구분 |

처리 중 카드 목록/상세/저장 요청을 함께 보내 DB pool 대기와 실제 사용자 지연을 본다.
FE Network·서버 단계 시간·DB connection/pool 대기를 연결하고 browser/서버 request ID를 보존한다.
무제한 동시성, 프레임/입력 삭제, 오류를 miss로 변환해 시간을 줄이는 변경은 허용하지 않는다.

## 초기 제품 목표 — 측정 전 제안, 달성 결과 아님

- 버튼 클릭 피드백 100ms 이내를 우선 목표로 삼되 실제 기기에서 측정한다.
- 일반 목록/상세/단순 저장은 정상 네트워크 p95 2초를 초기 검토 목표로 삼는다.
  업로드 전송·임베딩 승인·전체 추출은 같은 범주에 넣지 않는다. n·오류/timeout도 보고한다.
- 업로드 서버 접수/질문 응답 목표는 상위 MVP 계약을 따른다. 추출 총 시간은 입력 유형/길이별로
  기준선 이후 허용 범위를 사전 고정한다. 검증 없이 ‘몇 초 안에 완료’라고 안내하지 않는다.
- 품질 주 지표/허용 범위는 결과를 보기 전에 자료별 기대 사실·필수 규격/주의/조건과 함께 고정한다.
  숫자·단위·규격·부정·조건의 필수 회귀 악화, 미승인 공개·타 매장 노출은 0건 필요.

## 출시 인수

1. 지원 자료의 최소 흐름이 실제 화면/API/DB에서 완료되고 실패 자료의 대안이 동작한다.
2. 점주가 승인할 값/주의/근거를 실제로 볼 수 있고 공개/초안/제외가 유지된다.
3. 추출 중 일반 요청, 재시작 복구, 중복/느린 응답·부분 실패를 검증한다.
4. 실제 운영 reader의 승인/질문 충분성/안전 shim을 확인한다. known unsafe 자유생성 경로는 격리한다.
5. 정적 검사·API/DB·핵심 E2E·production build·모바일 확인이 통과한다.
6. 지원 범위/실측/제한/복구 방법/비용 관측과 배포·rollback 절차를 남긴다.

측정하지 않은 목표는 보류다. 계획만으로 ‘실사용 가능’, unit 통과만으로 ‘추출 잘됨’이라 체크하지 않는다.
