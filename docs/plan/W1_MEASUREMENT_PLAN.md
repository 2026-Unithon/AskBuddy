# 채점기 교정과 측정 구조 — 구현 계획

작성 2026-09-15 · 상태: **교정 코드 구현·합성/격리 DB 검증 완료, 사람 검토·과거 재평가 미완료** · 선행: W0 기준선 측정 완료

현재 인수 범위는 [교정 검증 기록](../review/W_MEASUREMENT_FIXES_20260915.md)을 따른다.
①에는 출력 채점기의 속성 선확인·전체 값 비교와 원장 속성/단위 검사를 추가했다.
`--detail` 오류 및 W 임베딩 연결 수명·원가 계측도 함께 보강했다.
②의 네 상태는 평가용 메타데이터이며 제품 snapshot의 `ALL_APPROVED_VARIANTS`를
평가의 `COMMON`으로 자동 변환하거나 사람 확인을 대체하지 않는다.
③⑤는 중앙값 성능·만장일치 안정성·전체 반복 안전성 코드와 회귀를 구현했다.
④의 BASE/BASE-AA·W1/W1-AA는 실행 당시 입력 snapshot이 없어 재평가를 보류했다.
옛 판정만으로 재평가하지 않으며 모델 재호출·holdout 개봉도 하지 않는다.
①의 실제 보류/확신 표본 사람 검토가 끝나기 전 ② 라벨 확정·품질 승격은 하지 않는다.

이 계획이 필요한 이유는 하나다. **지금 채점기가 오답을 정답으로 통과시킨다.**
그래서 W1 구조 변경이 실제 개선인지 측정 부작용인지 가릴 수 없다.
채점기를 고치기 전에는 어떤 개선도 주장하지 않는다.

근거는 [W0_BASELINE_20260915.md](../review/W0_BASELINE_20260915.md) 와 R 검토 회신이다.

## ① 채점기 오통과 차단

### 무엇이 잘못됐나

정답 `음료A / ICE / 우유량 / 225ml` 에 대해 아래 카드가 **전부 `COVERED`** 로 통과한다.
합성 입력으로 재현했다.

| 카드 내용 | 실제 문제 |
|---|---|
| `음료A HOT 우유 225ml, ICE 우유 275ml` | 규격과 값이 뒤바뀜 |
| `ICE 음료A 우유 225g` | 단위가 다름 |
| `ICE 음료A 우유 225ml는 잘못된 값이고 275ml를 넣는다` | 정답 값을 명시적으로 부정 |
| `ICE 음료A 우유는 넣지 않는다 225ml` | 금지인데 지시로 통과 |

원인은 현재 규칙이 **낱말·숫자가 같은 카드 안에 있는지만** 보기 때문이다.
대상·값·규격을 각각 확인하지만, 셋이 **서로 올바른 관계로 묶여 있는지**는 보지 않는다.

### 어떻게 고치는가

확인해야 할 관계는 이 사슬이다.

```
대상 → 속성 → 값·단위 → 적용 규격·조건 → 예외·부정 여부
```

낱말·숫자 겹침은 **대조 후보를 찾는 데만** 쓰고, 그 자체를 최종 판정으로 쓰지 않는다.

추가할 차단 규칙:

- **단위 일치** — 값에 단위가 있으면 카드의 같은 숫자에 붙은 단위가 같아야 한다 (`225ml` ≠ `225g`)
- **부정 검사** — 정답이 `AFFIRM` 인데 카드가 그 값을 부정하면 통과시키지 않는다
- **정정 문장** — `잘못된`·`틀린`·`아니라`·`대신` 이 값 근처에 있으면 자동 확정하지 않는다
- **규격 교차** — 한 카드에 규격이 둘 이상이면, 정답 규격에 붙은 값이 정답 값과 같아야 한다
- **같은 단위 다른 값** — 같은 단위의 다른 숫자가 함께 있으면 어느 것이 이 사실인지 자동으로 못 정한다

### 자동으로 못 정하는 것은 어떻게 하나

**통과시키지 않고 보류한다.** 새 판정 `UNDETERMINED` 를 둔다.

보류는 실패가 아니다. 다만 **"확인했다" 로 세지 않는다.**
`COVERED` 만 승격 판정의 분자로 쓰고, 보류 건수를 항상 함께 보고한다.

### 사람이 할 일의 크기

실측했다. store-b 카드 31장 · 정답 48건 기준:

```
COVERED 판정      22건
자동 확정 불가      1건  (5%)
```

278건 전체로 늘려도 **6~10건** 규모다. 자동 판정이 멈추지 않는다.
(이 측정은 위 차단 규칙의 시제품으로 잰 값이고, 규칙이 늘면 보류도 늘어난다.)

### ② 로 넘어가기 전 검증

고친 채점기가 제대로 고쳐졌는지는 **사람 표본**으로만 확인할 수 있다.
두 묶음을 본다. 한쪽만 보면 검증이 되지 않는다.

| 묶음 | 왜 보나 | 규모 |
|---|---|---|
| 채점기가 **보류**한 것 | 판정을 내려준다 | 6~10건 |
| 채점기가 **COVERED 라 확신**한 것 중 무작위 | 확신이 틀린 비율을 잰다 | 10~15건 |

두 번째가 핵심이다. 위 오통과 4건은 **전부 보류 표시조차 없이 확신한 것**이었다.
보류만 보면 이런 것은 영원히 걸리지 않는다.

이 표본으로 채점기를 **고치지 않는다.** 그 20건에 맞추면 그 20건만 맞추는 채점기가 된다.
규칙은 원리로 만들고, 표본은 오통과·오탈락 비율을 재는 데만 쓴다.

## ② 사실 단위 적용 범위 4상태

### 왜 대상 단위로는 부족한가

현재 구현은 **대상**에 규격 축이 있는지만 본다 (정답지에 서로 다른 규격이 둘 이상 나오면 축이 있다).
그러나 **같은 대상이라도 사실마다 적용 범위가 다르다.**
같은 음료에서 우유량은 규격별이고 세척 규칙은 규격 공통일 수 있다.

`규격 축이 존재한다` 와 `이 사실이 규격별로 달라진다` 는 별개다.

### 네 상태

| 상태 | 의미 | 카드에 규격이 없으면 |
|---|---|---|
| `SPECIFIC` | 특정 규격에만 적용 (ICE 전용 우유량) | 감점 — 다른 규격에 잘못 적용될 수 있다 |
| `COMMON` | 여러 규격에 공통 적용이라고 **확인됨** | 감점하지 않는다 |
| `NOT_APPLICABLE` | 이 업무 사실에 온도·사이즈 구분이 없다 | 감점하지 않는다 |
| `UNKNOWN` | 적용 범위를 아직 확인하지 못했다 | 판정하지 않고 보류 |

### 지켜야 할 원칙

**`null` 이나 라벨 누락을 `COMMON` 이나 `NOT_APPLICABLE` 로 바꾸지 않는다.**
모르는 것은 `UNKNOWN` 이다. 이것은 R 쪽 원칙과 같고, 양쪽이 같은 규칙을 쓴다.

자동 추론은 `NOT_APPLICABLE` 후보를 **제안**하는 데까지만 쓴다.
정답지에 규격이 하나뿐인 대상은 후보로 뽑되, 확정은 사람이 한다.

### 대상 축과 함께 쓴다

대상 단위의 축 정보(`variant_axis`)는 유지한다. 사실 단위 적용 범위가 그 위에 얹힌다.
축이 없는 대상의 사실은 자동으로 `NOT_APPLICABLE` 이고, 축이 있는 대상의 사실만
`SPECIFIC` / `COMMON` / `UNKNOWN` 을 가른다.

## ③ 안정성 저하를 별도 차단 조건으로

### 만장일치만 쓰면 생기는 구멍

```
기존:  성공 / 성공 / 성공     (만장일치)
변경:  성공 / 성공 / 실패     (갈림 → 비교에서 제외)
→ 보고: "악화 0건"
```

필수 사실이 항상 되던 것에서 1/3 실패로 바뀌었는데 게이트를 통과한다.
현재 구현은 흔들림 **건수**만 옆에 적을 뿐 **방향**을 세지 않는다.

### 어떻게 고치는가

두 군의 안정성 변화를 별도 범주로 센다.

| 변화 | 뜻 | 처리 |
|---|---|---|
| 안정(성공) → 갈림 | 되던 것이 흔들리기 시작 | **차단 조건.** 승격하지 않는다 |
| 갈림 → 안정(성공) | 흔들리던 것이 안정됨 | 개선으로 보고 (승격 분자에는 넣지 않는다) |
| 안정(실패) → 갈림 | 안 되던 것이 가끔 됨 | 개선 후보로 보고 |
| 갈림 → 갈림 | 판정 불가 | 건수만 보고 |

`must_have` 에서 `안정(성공) → 갈림` 이 하나라도 있으면 승격하지 않는다.

**미판정 필수 사례가 있으면 "악화 0건 확인" 으로 적지 않는다.**

---

## ④ 같은 기준으로 재평가

①②③ 을 적용하면 점수가 달라진다. **그 변화는 모델 개선이 아니다.**

- 기준선(BASE·BASE-AA 6회)과 W1(W1·W1-AA 6회)을 **같은 채점기로 다시 채점**한다
- 추출 산출물은 이미 저장돼 있으므로 재추출하지 않는다
- 재평가 전 수치와 재평가 후 수치를 같은 표에 나란히 적지 않는다. 기준이 다르다
- 재평가로 올라간 점수를 개선으로 보고하지 않는다

재평가 뒤에야 "W1 구조 변경이 개선인가" 를 물을 수 있다.

## ⑤ 중앙값(성능) + 만장일치(안정성) + 전체 반복(안전성)

하나의 대표값으로 성능·안정성·안전성을 모두 판정할 수 없다. 역할을 나눈다.

| 판단 | 기준 |
|---|---|
| 전체 성능 개선 | 고정 분모에서 반복별 성공 수 차이 Δᵢ 의 **중앙값** |
| 사실·질문별 안정성 | 매번 성공 / 매번 실패 / 반복 간 변동을 **별도 보고** |
| 안전성 | **모든 반복**의 오류·악화를 확인한다. 불안정 사례도 제외하지 않는다 |

중앙값 단독도 충분하지 않다. 전체 성공 수가 늘면서 특정 필수 사실이 악화될 수 있다.
따라서 **대표 개선량과 항목별 안전 조건을 함께** 적용한다.

D18 의 `최소 3회 · 중앙값 · 2/3 양의 방향 · 최소 개선량` 은 개발 단계의 판단 규칙으로 유지한다.
다만 **통계적 확신과 구분한다.** 3회 통과나 A/A 한 번의 순증 0 이 개선의 확실성을 증명하지 않는다.
반복을 늘린다고 관측된 최댓값−최솟값이 반드시 줄어들지도 않는다 — 범위는 표본이 늘면 오히려 커진다.

### 실험 전에 고정할 것

결과를 보기 전에 정한다. 보고 나서 정하면 그 실험은 탐색이지 검증이 아니다.

- 정답·채점기·입력 snapshot 버전과 전체 분모
- 반복 수, 실행 순서, 실패·미판정 처리 방법
- 대표 개선량과 안전·비용·지연 조건
- 결론이 불명확할 때의 추가 실험 범위

## 이 계획이 손대지 않는 것

- **W 와 R 의 성공 단위는 다르다.** `한 카드 안에서 확인` 은 W 의 카드 완결성 평가 규칙이다.
  여러 승인 근거를 적절히 인용하는 R 답변까지 실패로 만들지 않는다.
  의미 정확성 원칙은 공유하되 성공 단위는 각자 정의한다.
- **`ASSEMBLY` 는 손실 위치를 좁히는 진단이다.** 채점기 오류나 참조 연결 누락까지
  배제하기 전에는 원인을 확정했다고 말하지 않는다.
