# 15단계 — 영속 작업 처리와 운영 인수

## 15.1. 재시작 가능한 worker

- [ ] FastAPI `BackgroundTasks`에만 의존하지 않도록 Railway worker 프로세스를 분리한다.
- [ ] DB job을 worker가 claim하고 처리하도록 lock을 둔다.
- [ ] heartbeat 또는 lease 만료 뒤 중단된 작업을 다시 회수한다.
- [ ] retry와 프로세스 재시작이 카드·질문·알림을 중복 생성하지 않게 한다.
- [ ] 화면을 닫아도 작업이 계속되고 재진입 시 상태가 복원되는지 확인한다.

## 15.2. Supabase·Railway·Vercel 배포

- [ ] 최종 코드와 migration 순서를 동결한다.
- [ ] 운영 Supabase schema와 data를 Git 제외 경로에 백업한다.
- [ ] local DB 재구축, verify SQL, API/DB 테스트를 실행한다.
- [ ] linked `supabase db push --dry-run`으로 예상 migration만 확인한다.
- [ ] 운영 migration 적용 후 migration list와 read-only verify를 확인한다.
- [ ] Railway API와 worker를 배포한다.
- [ ] Vercel Web을 배포한다.
- [ ] 운영 API URL, CORS, Supabase, AI, VAPID, ingest mode와 제한값을 검증한다.
- [ ] Web → API → DB와 `/health` smoke test를 실행한다.
