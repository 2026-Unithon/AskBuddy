# 13단계 — 평가 기준선 (쓰기 경로 먼저, 그다음 읽기 경로)

> **순서 원칙: 추출이 검색보다 먼저다.**
> 파이프라인은 둘이다. 쓰기(자료 → 카드)와 읽기(질문 → 답변).
> 추출이 사실을 흘리면 카드에 그 내용이 없고, 검색은 없는 것을 찾지 못한다.

## 13.2. 자료 확정과 정답지 라벨링

정답지 없이는 쓰기·읽기 어느 쪽도 채점할 수 없다. **여기가 13단계의 실질적 시작점이다.**

### 13.2-1. 평가용 자료를 먼저 확정한다

- [ ] 기준선을 잴 매장 자료를 정한다. 실제 카페 자료가 원칙이고, 확보가 어려우면
      현실적인 가상 매장을 만든다. 어느 쪽인지 문서에 명시한다.
- [ ] 승인 카드가 **최소 30장** 나오는 분량이어야 한다.
      카드 3장으로는 모든 지표가 1.0 으로 나온다. 잘해서가 아니라 너무 쉬워서다.
- [ ] 자료를 투입하고 카드를 승인한 뒤에 라벨링한다.
      **라벨링 후에 자료를 추가하면 `expected_card_ids` 가 전부 어긋나 골든셋이 무효가 된다.**
- [ ] 원본 자료와 DB 백업은 Git 에 커밋하지 않는다.

### 13.2-2. 정답지는 두 벌이다 — 같은 읽기 작업에 얹는다

자료를 두 번 읽지 않으려면 한 번에 둘 다 만든다.

| 정답지 | 형태 | 채점 대상 |
|---|---|---|
| **사실 정답지** | 원본 자료 → 그 안에 담긴 업무 사실 목록 | 추출 손실(E-O0) · 13.3 추출 하네스 |
| **골든셋** | 질문 → 기대 카드·핵심 사실 | 검색·답변(E0) · 13.4 |

- [ ] **사실 정답지**: 원본(전사문·PDF·영상)을 사람이 읽고 "여기 담긴 업무 사실 N개" 를 적는다.
      각 사실에 출처 위치(페이지·타임스탬프)를 남긴다.
- [ ] **골든셋**: 30~50문항. 아래 13.2-4 의 구성 요건을 채운다.

### 13.2-3. 사람 판정은 필수다 (생략 불가)

MRR·nDCG 는 **정답을 판별하지 않는다.** 사람이 정해준 정답 대비 순서만 잰다.
`expected_card_ids` 는 채점의 입력이지 산출이 아니다. **라벨 품질이 하네스 전체의 천장이다.**

### 사람 판정은 필수다 (생략 불가)

MRR·nDCG 는 **정답을 판별하지 않는다.** 사람이 정해준 정답 대비 순서만 잰다.
`expected_card_ids` 는 채점의 입력이지 산출이 아니다. **라벨 품질이 하네스 전체의 천장이다.**

- [ ] **pooling 으로 라벨링한다.** 전수(질문 50 × 카드 50)는 불가능하다.
      각 질문을 현재 검색기로 돌려 상위 10개만 뽑고, 그 10개에만 관련/무관을 판정한다.
- [ ] **두 종류의 판정을 가른다.**
      - 매장 사실 관계("우유는 언더카운터 2단이 맞는가") → **점주만 안다. 점주 확인 필수**
      - 검색 관련성("이 질문에 이 카드가 관련 있는가") → 팀이 판정 가능
- [ ] 판정자·판정일을 남긴다. 누가 정한 정답인지 모르면 나중에 이견을 못 푼다.
- [ ] **검색 로직을 바꾸면 풀을 다시 판정한다.** pooling 의 약점은 현재 검색기가 한 번도
      못 끌어온 카드가 영원히 '정답 아님'으로 남는 것이다. 14단계에서 검색을 바꾸면
      새로 올라온 카드를 재판정해야 전후 비교가 공정하다.

- [ ] 각 질문에 기대 카드 ID, 핵심 사실, 답변 가능 여부, 카테고리, 근거를 라벨링한다.
- [ ] 숫자·온도·시간·용량·고유명사·부정문·예외를 포함한다.
- [ ] 정식어, 동의어, 줄임말, 현장 은어, 오타와 음성 인식 변형을 포함한다.
- [ ] 답이 없는 질문과 다른 매장에만 답이 있는 질문을 포함한다.
- [ ] 안전·위생·응급 질문의 거절 또는 직접 확인 경로를 포함한다.
- [ ] `IDENTICAL`, `NEW`, `SUPPLEMENT`, `CONFLICT` Q&A 관계를 각각 포함한다.
- [ ] Q&A 기반 카드의 카테고리·로드맵·FAQ 반영을 포함한다.
- [ ] 검색 로직을 바꾸기 전 현재 기준 실행 결과를 저장한다.

      원본에 있는 비율) · 숫자 왜곡 건수 · 중복 카드 · 근거(페이지·타임스탬프) 정확도.
- [ ] 처리 시간·토큰·원가를 자료 1건당으로 기록한다. 원화로도 환산한다.

## 13.4. 기준선 측정 — E-O0 먼저, 그다음 E0

- [ ] **`E-O0` 추출 손실** — 사실 정답지 대비, 원본에 있는데 카드에 없는 비율.
      **이것이 시스템 정확도의 진짜 천장이다.** 여기서 30% 를 흘리면 검색·생성을
      완벽하게 만들어도 70% 를 못 넘는다. 그리고 **검색을 고쳐서는 절대 안 올라간다.**
- [ ] `E-O0` 결과에 따라 다음 단계를 가른다:
      - 손실이 크다 → **14.1 추출 개선을 먼저 한다.** 검색 작업은 그 뒤다
      - 손실이 작다 → 읽기 경로로 넘어간다
- [ ] **`E0` 읽기 기준선** — 골든셋으로 현재 설정 그대로 측정. 검색 로직을 바꾸기 전에 찍는다.
- [ ] 두 결과를 `이관경계_실험설계.md` 7절 실험 기록에 남긴다.

## 14.1. 입력·추출 품질 (구 14.4)

- [ ] 중복·욕설·위험 표현·브랜드 고유 표현을 정규화하고 구분한다.

## 14.5. 하이브리드 검색과 LLM reranker (구 14.6)

필수 비교군:

| 실험군 | 용어사전 | LLM reranker |
|---|---:|---:|
| 기준 | 미적용 | 미적용 |
| 사전 효과 | 적용 | 미적용 |
| reranker 효과 | 미적용 | 적용 |
| 최종 후보 | 적용 | 적용 |


- [ ] lexical/BM25와 vector 점수를 결합해 상위 후보를 만든다.
      결합은 **RRF(Reciprocal Rank Fusion)** 로 한다. BM25 점수와 코사인 유사도는 척도가 달라
      가중합이 성립하지 않는다. RRF 는 순위만 쓰므로 이 문제를 우회한다.
      효과는 13단계 하네스의 MRR·nDCG@10 전후 비교로 판정한다.
      상수 `k`(관례 60)도 가정하지 말고 하네스로 정한다.
- [ ] **`RETRIEVAL_THRESHOLD` 게이트는 RRF 앞단에 그대로 둔다.**
      RRF 는 순위만 다루므로 후보가 전부 형편없어도 1등을 뽑아준다.
      miss 판정은 계속 원 점수로 한다. 안 그러면 `false_block_rate` 는 내려가고
      근거 없는 답변이 올라간다.
- [ ] 질문과 같은 매장의 승인된 현재 카드만 후보에 포함한다.
- [ ] 상위 후보 수를 제한하고 질문과 카드만 LLM reranker에 전달한다.
- [ ] reranker는 순위, 관련도, answerable, 짧은 근거만 구조화 JSON으로 반환한다.
- [ ] reranker가 카드에 없는 사실이나 최종 사용자 답변을 만들지 못하게 한다.
- [ ] timeout, schema 오류, 모델 오류 시 기존 검색 순위로 폴백한다.
- [ ] 기능 플래그로 즉시 비활성화할 수 있게 한다.
- [ ] **벤더 호출부를 어댑터 인터페이스 뒤로 뺀다.** 교체가 플래그 한 줄이 되지 않으면
      비교 실험 자체가 불가능하다. 실험의 전제조건이다 (`이관경계_실험설계.md` 6-4절).
- [ ] 한 단계에는 한 벤더만 쓴다. 단계별로는 달라도 된다.
- [ ] latency, token, 비용, 순위 변화와 정답률을 기록한다.
- [ ] 사전·hybrid·reranker 네 비교군을 13단계 골든셋과 실제 입력셋으로 평가한다.
- [ ] 근거 없는 답변률 또는 매장 격리가 악화되면 배포하지 않는다.
- [ ] 검색 결과가 충분해도 최종 근거 검증과 안전 폴백은 유지한다.
