완료: 설정·원시 JSON·Markdown 리포트가 재현되고 정답지 확인 상태가 명시된다. **사실 손실률을 곧바로 질문 정확도의 수학적 상한으로 쓰지 않는다.** 질문별 필요한 사실 집합과 실제 답변 가능 범위를 별도로 평가한다.

## W1. 입력 분할과 사실 원장 선저장 — 구 13.3-1·13.4

- [ ] source segment를 페이지·표·블록·메시지·시간 구간으로 만들고 원본 위치·해시를 보존한다.
- [ ] PDF는 페이지별 텍스트 품질과 표 행·열 관계를 확인하고 필요한 페이지 이미지를 전달한다. 일부 텍스트가 읽힌다고 모든 이미지를 생략하지 않는다.
- [ ] 영상은 frame ID·시각과 STT 구간, 음성은 앞뒤 문맥·timestamp, 카톡은 화자·날짜·질문/답변과 번복 문맥을 보존한다.
- [ ] `extract_facts` 전용 프롬프트·schema를 만든다. 카드 제목·2~3문장 요약을 먼저 만들지 않고 확인된 사실만 추출한다.
- [ ] 원시 응답·파싱 결과를 카드 조립 전에 영속 저장한다. schema 오류·출력 잘림·부분 실패·`unresolved`를 구간별 기록한다.
- [ ] 단위·규격·조건의 추정 채우기와 존재하지 않는 segment 참조를 거절한다. 텍스트 인용 존재 검사와 이미지/의미 정확도 평가를 구분한다.
- [ ] 입력/출력 token 상한, 구간 크기·중첩, 동시 호출 수·timeout·retry를 제한한다. 잘린 출력은 재분할/이어받기로 복구하고 조용히 성공 처리하지 않는다.
- [ ] 같은 요청 재시도는 중복을 만들지 않고 모델·프롬프트 변경 재추출은 별도 run으로 남긴다. 중복 canonical fact여도 각 evidence occurrence를 보존한다.
- [ ] 재사용 키에 매장·원본/segment 해시·모델·프롬프트·schema·설정 버전을 포함한다. 평가 정답을 런타임 추출 입력에 넣지 않는다.

검증: 한 구간·조립 호출 실패에도 성공 구간의 facts가 남고 재처리로 복구된다. 동일 재시도는 facts·job 결과를 중복 생성하지 않으며 숫자·부정·조건과 segment 연결을 검사한다.

## W2. 사실 revision·대상 통합·충돌 — 구 13.3-1~13.3-3

- [ ] 서버 확정 `entity_id`와 규격을 도입하고 raw 대상·값을 보존한다. 별칭 정규화가 HOT/ICE·사이즈를 합치지 않게 한다.
- [ ] 수정은 불변 fact revision으로 남기고 추출 원문·점주 정정·적용 시점을 구분한다. `corrected_value`는 이관 입력이며 공개 근거 포인터가 아니다.
- [ ] 업로드·점주 답변에 원장 출처를 부여한다. 파일 source가 없는 OWNER_ANSWER를 임의 파일 출처나 무출처 사실로 만들지 않는다.
- [ ] 동일 대상·호환 규격의 다중 자료 사실을 모으되 상충 값은 함께 보존한다. 단어 유사도만으로 대상을 확정하지 않는다.
- [ ] 기존 `IDENTICAL | NEW | SUPPLEMENT | CONFLICT` 제안을 재사용한다. 업로드는 네 관계 모두 검수하고 매칭된 기존 카드 전체와 양쪽 근거를 보여준다.
- [ ] 자료 권위·최신성은 정렬 참고로만 사용하며 자동 확정하거나 점주 선택을 강제하지 않는다.
- [ ] 새 사실의 대상·규격·의존 조건에 영향받는 카드만 재조립한다. 수동 분류·점주 수정과 영향 없는 카드 ID·공개 버전을 보존한다.
- [ ] 잘못 합친 대상의 분리·연결 수정도 이력을 남기고 공개본을 자동 변경하지 않는다.

검증: 영상 순서+PDF 수량 통합, HOT/ICE 분리, 수치 충돌, 매장별 별칭 격리, 동일 재투입·수정·대상 분리가 기대와 일치한다. 초안 실패나 관계 오판을 되돌려도 공개본은 보존된다.

## W3. 사실 참조로 카드 조립·검수 — 구 13.3-1b~1c·13.4~13.5

- [ ] 조립 모델은 fact revision/블록 참조·배치·표시 힌트만 제안한다. 수량·단위·조건·부정·예외를 새 값으로 발급하지 않는다.
- [ ] 서버가 참조 허용 목록, 대상·규격, 필수 조건·예외·선행 단계와 순서를 검증하고 콘텐츠를 렌더링한다.
- [ ] 제목 → 수치 → 순서 → 목록 → 근거의 줄 문법을 유지한다. 없는 블록은 생략하며 고정 필드·분량 제한 때문에 사실을 버리지 않는다.
- [ ] 대상이 크면 의미 단위와 dependencies를 유지해 관련 카드로 분리한다. 숫자만 떼거나 필수 조건을 다른 화면에서 찾게 하지 않는다.
- [ ] 조립 실패는 원장을 보존한 검수 대기나 검증된 RAW 블록으로 처리한다. 실패 문장을 삭제해 완성 카드로 위장하지 않는다.
- [ ] 추출 occurrence마다 `LINKED / REVIEW_PENDING / EXCLUDED(reason)` 처분을 기록한다. 미처리·잘못된 연결·필수 문맥 누락을 별도 측정하고 과도한 제외/대기를 품질 향상으로 세지 않는다.
- [ ] 검수 화면에 값·규격·조건·근거·원문을 제시하고 수정·추가·제외를 허용한다. 숫자가 없는 금지·예외도 숨기지 않는다.
- [ ] 자유 편집으로 업무 의미가 바뀌면 새 점주 작성 사실/블록으로 기록하고 재승인한다. 문구 수정이 미검증 사실 변경의 우회로가 되지 않게 한다.
- [ ] `RECIPE | TASK`는 렌더링 힌트로 사용한다. 체크리스트·근거 이미지·승인 정보를 연결하며 예상 질문은 검색 파생물로 구분한다.

검증: 타 매장/존재하지 않는 참조, HOT/ICE 수치 교환, 부정·조건·예외 삭제, 순서 변경을 차단한다. 승인 미리보기와 저장 콘텐츠가 같고 occurrence가 처리 결과 없이 사라지지 않는다.

검증: 임베딩 실패·동시 수정·제외·중복 요청, 미승인 정정값과 공개 구버전, 과거 인용 조회를 통합 테스트한다. 저장·검색·화면이 같은 공개 버전을 가리키는 실제 snapshot을 R에 인계한다.

## R0. 기준선·인증·평가 — 구 14.1~14.3·14.7

- [ ] PostgreSQL·pgvector에서 lexical/vector 후보를 독립 회수하고 한국어 토큰·숫자·단위·짧은 메뉴명을 실자료로 검증한다.
- [ ] 후보를 합쳐 RRF 등 사전 고정 방식으로 재정렬한다. 모든 lexical 후보 앞에 공통 vector 하한을 두지 않는다.
- [ ] vector score·lexical score·RRF 순위·답변 가능성을 구분한다. cutoff·후보 수·앵커 감점은 dev에서 정하고 miss는 R3 근거 충분성까지 확인한다.
- [ ] query variants는 추정 사실을 포함하지 않는 검색용 질문으로만 쓰고 효과·비용을 별도 평가한다.

검증: 같은 대상 다른 속성(위치/가격/수량), HOT/ICE·크기, 별칭·오타, lexical만 찾는 정답, 전부 무관한 후보에서 기대와 일치한다.

## R3. 근거 충분성·reranker·행동 — 구 14.3~14.6

- [ ] 동일 매장·현재 공개 버전, 대상·속성·규격, 필수 조건·예외·선행 단계의 완전성을 확인한다.
- [ ] 규격이 여러 답으로 갈리면 `CLARIFY`, 지식 부족·미확정 충돌이면 `ESCALATE`, 충분하면 `ANSWER`로 계획한다. 정책 분기는 C0의 고정 안내를 따른다.
- [ ] LLM reranker 어댑터를 구현·평가한다. 허용된 후보 ID·관련성·사유만 반환하게 하고 후보 밖 ID를 거절한다.
- [ ] `answerable=true`나 RRF 1위만으로 답변을 허용하지 않는다. 모델 관련성 추정은 권한·공개·구조 검사의 대체재가 아니다.
- [ ] timeout·JSON/schema 오류 시 기존 순위로 돌아가도 동일한 근거 충분성 검사를 유지한다.
- [ ] 사전·hybrid·reranker를 한 축씩 비교하고 통합 조합도 평가한다. 구현·평가는 필수지만 효과 없는 reranker를 기본 활성화하지 않는다.
- [ ] 코드만으로 의미 정확도를 보장할 수 없는 사례를 구분하고 사람 평가·되묻기로 다룬다.

검증: 답할 수 있는데 차단한 경우와 잘못 통과한 답변을 각각 집계한다. 같은 대상의 무관 속성이 선택돼도 ANSWER가 되지 않는 사례를 포함한다.

## R4. 승인 의미 단위로 답변·인용·재질문 — 구 14.4·14.7

- [ ] 모델은 행동·허용된 fact revision/블록 참조·템플릿·누락 슬롯을 제안한다. 새로운 수량·조건·금지문을 자유 생성하는 경로를 기본으로 쓰지 않는다.
- [ ] 서버가 값을 대상·규격·속성에 연결해 렌더링하고 필수 조건·예외·선행 참조를 포함한다. 간결하게 만들려고 문맥을 생략하지 않는다.
- [ ] 수량·위치·금지는 검증된 템플릿, 복잡한 절차는 승인 블록으로 출력한다.
- [ ] 정확한 공개 card/version을 `message_citations`로 저장한다. 답변·인용 저장과 현재 공개 재검사는 같은 성공 단위로 처리한다.
- [ ] legacy RAW 폴백은 현재 승인 버전이며 질문의 충분한 근거일 때만 허용한다. 첫 카드 존재만으로 원문을 답으로 반환하지 않는다.
- [ ] `CLARIFY` 턴과 슬롯을 보존하고 응답 사용자·매장·세션·TTL을 검사한다. 되묻기 반복 상한 뒤 명확한 다음 행동을 제공한다.
- [ ] ESCALATE의 원문·resolved_query·확정 슬롯/context snapshot을 저장하고 점주 UI에 보여준다. 서로 다른 음료를 말한 두 직원의 ‘그럼 따뜻한 건?’이 다른 pending이 되고, 동일 문맥만 묶여 해당 occurrence에 답변이 전파되는지 검증한다.
- [ ] `ESCALATE`는 질문 저장 성공 후 WAITING·점주 알림을 표시한다. 저장/인프라 실패는 오류로 응답하고 지식 없음으로 위장하지 않는다.
- [ ] `REFUSE/SAFE_ROUTE`는 승인된 정책 문구를 사용하며 자동 pending을 만들지 않는다. 별도 확인 요청이 있을 때만 ESCALATE로 이어진다.
- [ ] 숫자 교환·단위 오연결·부정/예외/조건 삭제·순서 변경·잘못된 인용·prompt injection을 회귀 사례로 고정한다.

완료: 구조적 반례가 차단되고 정답 근거 주입 시 답변 정확도·false block·지연/비용을 분리 측정한다. 실제 응답 품질은 J1에서 재확인한다.

## R5. 점주 답변 루프·직원 UX·읽기 완료 — 구 14.2·14.7

- [ ] R은 질문 occurrence·점주 원문 답변·알림·FAQ를 소유하고 OWNER_ANSWER event/outbox로 W의 `knowledge_apply`에 넘긴다. `knowledge_loop`를 중복 소유하지 않는다.
- [ ] 점주가 제출한 원문 그대로의 `NEW/IDENTICAL`은 기존 승인 경로를 유지한다. 모델 파생 facts는 별도 검수하며 `SUPPLEMENT/CONFLICT`는 기존 카드와 함께 확인한다.
- [ ] W 공개 성공 후 FAQ·학습·재질문 검색을 갱신한다. 점주 원문 저장 성공과 지식 발행 성공을 구분한다.
- [ ] 여러 직원의 occurrence·답변 전파를 보존한다. 앱 내 알림을 정본으로 하고 Push 거절·만료·404/410·실패에도 확인 경로를 제공한다.
- [ ] 레시피 대량 조회·다운로드·내보내기 권한과 감사 로그·점주 조회 이력을 구현한다. 화면 복사 제한만으로 보호가 완성됐다고 주장하지 않는다.
- [ ] recall@k·MRR/nDCG, 완전한 근거 집합 회수, 의미적 오답·인용 오류, 과도한 차단, 재질문 적절성·완료율, p50/p95·비용을 보고한다.
- [ ] 실제 snapshot별 질문 30~50문항 이상을 기본 커버리지로 준비한다. 문항 수만으로 일반화·희귀 오답률을 입증하지 않는다.

R 완료: C0/R0~R4 계약·보안·회귀와 제품 루프가 fixture에서 동작하며 snapshot 교체만으로 재평가할 수 있다. 사전·hybrid·reranker의 독립·통합 효과가 기록되고 승격은 실험설계 판정표를 따른다.

# J0~J3. 통합 검증과 15단계 운영 인수

## J0. 조기 계약 통합 — C0 이후 반복, W 주도·R 검토

- [ ] W snapshot을 R fixture schema와 대조하고 정상·오류·legacy 생산자/소비자 테스트를 CI에 넣는다.
- [ ] 양쪽 완료 전 작은 합성 자료로 원장→미리보기→승인→검색→인용을 관통한다.
- [ ] schema·publication/index revision·오류 변경 시 fixture와 소비자 테스트를 함께 갱신한다.
- [ ] migration 순서·rollback 범위·기존 카드/인용 이관 건수·누락 목록을 로컬 검증한다.

## J1. 실제 종단 평가·엄밀 검토 — 공동, 상대 파이프라인 교차 검토

- [ ] W 실제 승인 snapshot·원본·정답지·코드·설정을 동결하고 합성 fixture 결과와 별도 보고한다.
- [ ] 원본으로 답할 수 있고 정책상 제공 가능한 `Q_source_A`와 기대 행동을 먼저 고정하고 `e2e_grounded_answer_rate`를 측정한다. W 누락/미승인 대기로 올바르게 ESCALATE해도 R 정책 성공과 종단 ANSWER 실패를 분리한다. snapshot별 Q_A 크기도 보고하며 결과에 따라 분모를 재라벨링하지 않는다.
- [ ] 같은 자료·질문으로 기준선, W만 변경, R만 변경, W+R 변경을 비교한다. 호환 불가 조합은 제외 이유와 비교 가능한 범위를 명시한다.
- [ ] 원본/추출 누락·왜곡, 카드 조립/검수 대기, 검색 누락, 잘못된 규격, 답변 오류, 검증 과차단, UI/저장 실패를 구분한다.
- [ ] 분모·코드/schema·모델·프롬프트·자료 hash·반복 수·단가/환율 시점을 고정한다. 불안정 사실·질문도 전체 분모에서 제외하지 않는다.
- [ ] 최소 3회와 A/A 동일 조건 대조군, 평균·실행별 분포·매장/유형별 결과·불확실성을 보고한다. 3회가 통계 보장은 아니며 표본 오답 0건을 절대 무오류로 쓰지 않는다.
- [ ] holdout은 후보·판정 기준·반복 횟수를 사전 등록한 뒤 한 캠페인으로 개봉하고 캠페인 중 튜닝하지 않는다. 결과를 보고 바꾼 후보에 같은 holdout을 봉인 검증으로 재주장하지 않는다.
- [ ] 매장/승인 위반, 숫자 연결·부정·필수 조건 변경 회귀는 0건을 요구한다. 일반 품질·false block·비용·지연은 실험설계의 사전 기준으로 승격/보류/기각한다.
- [ ] W가 R의 version·권한·조건 보존을, R이 W의 원장 보존·승인 snapshot·충돌을 교차 검토한다. 발견 사항마다 재현 조건·중요도·담당·수정·재검증 결과를 남긴다.

## J2. E2E·CI·영속 worker — 15.1 포함, W worker 주도·R UI/알림 검토

- [ ] 점주 1명·직원 2명으로 업로드→job→카드→승인→학습→질문→답변, miss→점주 답변→신규/보완/충돌→재질문을 자동화한다.
- [ ] 이동·뒤로가기·새로고침·포커스·재실행, 중복 클릭·느린 응답·부분 실패·retry, 긴 카드·30개 이상 목록·pagination을 확인한다.
- [ ] FastAPI `BackgroundTasks` 단독 처리에서 worker를 분리하고 DB claim/lease·heartbeat·만료 회수·retry·실패 격리를 구현한다.
- [ ] 구간·사실·제안·발행·질문·알림 단계별 checkpoint·멱등성을 검증한다. 프로세스 종료와 lease 경합을 주입해 복구한다.
- [ ] 외부 모델 요청 동안 DB 연결을 보유하지 않으며 동시 처리·큐 적체·timeout·비용에 상한을 둔다.
- [ ] CI에 lint `--max-warnings 0`, TypeScript typecheck, Python unit/API, migration/DB verify, 계약 테스트, 핵심 Playwright E2E, production build를 연결한다.
- [ ] 필수 검사 실패 시 배포를 차단하고 실패 구간을 추출·조립·발행·검색·답변·검증·화면으로 구분해 보고한다.

## J3. 운영 인수 — 구 15.2~15.4, 릴리스 주 담당 한 명 지정

- [ ] 운영 실행 권한·대상 환경을 확인하고 코드·migration 순서를 동결한다. 계획 체크 항목만으로 운영 실행 권한을 추정하지 않는다.
- [ ] 승인된 배포 작업에서 백업→로컬 재구축/verify→linked dry-run→운영 적용→read-only verify를 따른다. 원본·백업·비밀값은 Git에서 제외한다.
- [ ] Railway API·worker, Vercel Web, Supabase 호환 순서와 CORS·AI·VAPID·ingest 제한을 확인한다.
- [ ] 모든 W 조합에서 운영 legacy reader는 안전 shim(충분성 검사·승인 RAW·안전한 비답변)을 먼저 적용한다. 미패치 자유 생성 reader는 격리 평가 전용이며 v1이 표현 못 하는 CLARIFY는 v2 전환 오류/안내로 처리한다.
- [ ] 플래그·색인 전환·legacy 호환·rollback을 구분한다. 롤백해도 승인 이력·fact revision을 지우지 않는다. 알려진 취약 자유 생성 경로로 되돌리는 것을 안전한 롤백으로 부르지 않는다.
- [ ] `/health`와 Web→API→DB smoke, 기존 사용자·카드·질문·인용·알림 보존을 확인한다.
- [ ] iPhone PWA·Android Chrome·Desktop의 알림/fallback, 재시작 중 job 회수, QR→질문→답변→설문을 확인한다.
- [ ] worker/AI/Push 장애·비용 급증·대량 조회·색인 지연의 경보·복구·담당·알려진 제한을 기록한다.
- [ ] 실제 결과로 체크와 MVP 구현 현황을 맞춘다. 계획 갱신 완료와 제품 출시 완료를 구분한다.

# 실행 순서와 두 사람의 인계

| 병렬 구간 | W 담당자 | R 담당자 | 합류 조건 |
|---|---|---|---|
| 먼저 | C0 계약·fixture 공동 확정 | C0 계약·fixture 공동 확정 | 정상/오류 예시·검토 완료 |
| 1 | W0 기준선 + W1 입력·선저장 | R0 기준선·보안 + R1 fixture 소비 | J0 조기 계약 테스트 |
| 2 | W2 revision·통합 + W3 조립·검수 | R2 후보 검색 + R3 근거·rerank | 계약 변경 시 C0 재검토 |
| 3 | W4 발행 + W5 쓰기 평가 | R4 답변·인용 + R5 제품 루프 | 실제 snapshot 인계 |
| 4 | J1 실제 종단·교차 검토 | J1 실제 종단·교차 검토 | 사전 품질·비용·지연 게이트 |
| 5 | J2 worker·통합, J3 운영 인수 | J2 E2E·알림, J3 운영 인수 | CI·복구·데이터 보존·운영 확인 |

일정은 C0에서 작업 크기를 확인해 정한다. 고정 날짜를 추정해 약속하지 않는다. 기존 12.5는 화면·개발 기반, 13은 W, 14는 R, 15는 J2 worker와 J3으로 매핑한다.

W→R 인계에는 snapshot schema/version, 허용·거절 fixture, 실제 snapshot hash, fact/card revision 매핑, 공개/제외 이벤트·재시도 의미, 쓰기 평가 한계를 포함한다. R→W 인계에는 인덱스 준비 어댑터, OWNER_ANSWER 입력·발행 결과 계약, 답변 필수 조건 참조, 소비자 테스트·부족 근거 사례를 포함한다.

최종 체크는 구현·해당 위험을 검증한 테스트·반복 품질 결과·운영 인수가 충족될 때 닫는다. 이번 개정은 그 작업의 분담과 판정 기준을 갱신한 것이다.
