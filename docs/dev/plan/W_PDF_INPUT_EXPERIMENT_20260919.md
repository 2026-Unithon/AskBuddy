# PDF 입력 방식 비교 실험 — 사전등록

> **실행 전에 쓴다.** 결과를 보고 아래 기준을 바꾸면 실험이 아니다 (D17·D18).
> 2026-09-19 작성. 실행 결과는 `../review/` 에 별도로 남기고 이 문서는 고치지 않는다.

## 왜 하는가

`_preprocess_scan` 은 pypdf 로 뽑은 텍스트가 충분하면 PDF 원본을 모델에 넘기지
않았다. 그래서 글이 읽힌 문서의 표·사진 페이지가 통째로 사라졌다
([감사](../review/WR_IMPLEMENTATION_AUDIT_20260919.md) 결함3).

수정하면서 **"pypdf 텍스트가 Gemini 가 PDF 를 직접 읽는 것보다 정확하다"** 를
전제로 삼았는데, 이 전제는 측정된 적이 없다. 오히려 반대일 근거도 있다 —
pypdf 는 콘텐츠 스트림 순서로 뽑아 표의 행·열 관계가 사라지고, 다단 레이아웃이
섞이며, 띄어쓰기가 깨진다. 카페 자료의 레시피·가격표는 대부분 표다.

Gemini 에 PDF 를 넘기는 것은 OCR 이 아니다. 임베디드 텍스트와 레이아웃을 함께
본다. 따라서 "정확한 텍스트 vs 부정확한 비전" 이라는 구도 자체가 틀렸을 수 있다.

## 비교하는 축 — PDF 를 모델에 어떻게 넣는가

다른 것은 전부 고정하고 이 축만 바꾼다.

| arm | 입력 | 설명 |
|---|---|---|
| **TEXT** | pypdf 텍스트만 | 결함3 수정 **이전** 동작. 대조군 |
| **FILE** | PDF 원본만 | Gemini 가 페이지를 직접 읽는다. 텍스트 레이어 미사용 |
| **BOTH** | 텍스트 + PDF 원본 | 잃는 것이 없는 대신 페이지마다 비용 |
| **HYBRID** | 텍스트 + (그림 페이지가 있을 때만) 원본 | 결함3 수정본. 현재 기본값 |

`app.config.pdf_input_mode` 로 고른다. arm 은 **순수해야 한다** — TEXT 가 그림
페이지에서 원본을 붙이면 그것은 TEXT 가 아니라 HYBRID 이고, 비교가 성립하지 않는다.

글이 아예 없는 스캔본은 어느 arm 이든 원본을 넘긴다. 안 넘기면 빈손이라 arm 간
차이가 아니라 그냥 실패가 된다.

## 고정하는 것

| 항목 | 값 |
|---|---|
| 모델·온도 | `gemini-3.6-flash`, `extract_temperature=0.0` (D16) |
| `INGEST_MODE` | `real`. mock 결과는 모델 성능으로 집계하지 않는다 (D10) |
| 분모 | **dev SCAN 사실 85건** (store-a 57 · store-b 28). 필수 76건 |
| 대상 자료 | dev 매장의 SCAN 5건 (`--only-type SCAN`) |
| 매장 | `store-a`, `store-b` 만. **holdout(`store-c`·`store-d`)은 열지 않는다** |
| 채점기 | 현재 `SCORER_VERSION` (실행 시 run 에 기록된다) |
| 반복 | arm 당 **3회** (D17 최소) |
| A/A 대조 | TEXT 를 별도 라벨로 3회 더 돌려 대조군 자체의 변동 폭을 잰다 |
| 정답지 | `api/eval/data/<store>/truth/facts.json` 현재판. 실행 중 수정 금지 |

분모를 SCAN 으로 좁혔으므로 **전체 278건 기준 수치와 나란히 놓지 않는다.**
이 실험의 결과는 "PDF 입력 방식" 축에 대해서만 말한다.

## 읽을 지표

주 지표는 **E-O0 추출 손실**(원본에 있는데 카드에 없는 비율)이다. 함께 본다:

- `loss_stage` 분해 — EXTRACTION / ASSEMBLY / CARD_ONLY / OK
- 필수 사실(`must_have`) 누락 건수
- 잘못된 값·단위·규격 (채점기 v3 검사)
- 미판정(UNDETERMINED) 건수 — 분모에서 빼지 않는다
- 실패한 실행 — 분모에서 빼지 않는다
- 실제 token 사용량 (원장 `EVALUATION` 귀속). **요율표가 없으므로 금액이 아니라
  token 으로 보고한다** (`config/rate_card.json` 의 rate 가 null, D21 UNDETERMINED)

## 판정 규칙 — 미리 정한다

D18 을 따른다. 하나의 대표값으로 성능·안정성·안전성을 함께 판정하지 않는다.

- **성능**: 반복별 순증 Δᵢ 의 **중앙값**. 최댓값이 아니다
- **안정성**: 항목별로 매번 성공 / 매번 실패 / 갈림을 따로 보고한다.
  `안정(성공) → 갈림` 은 그 자체가 차단 조건이다
- **안전성**: **모든 반복**에서 필수 사실 악화가 있는지 본다. 한 번이라도 있으면
  악화로 적는다. 미판정이 남아 있으면 "악화 0건 확인" 으로 적지 않는다
- **최소 개선량**: 대조군 A/A 변동 폭을 넘지 못하는 차이는 **차이 없음**으로 적는다.
  A/A 폭은 실행 후에 확인하되, "폭을 넘어야 한다" 는 규칙은 지금 고정한다

3회·중앙값·2/3 방향 일치는 **개발 단계 판단 규칙이지 통계적 확신이 아니다**(D18).
반복을 늘려도 최댓값−최솟값은 줄지 않는다.

## 기본값 변경 조건

위 판정에서 어떤 arm 이 HYBRID 보다 나은 것으로 나와도, **이 실험만으로 제품
기본값을 바꾸지 않는다.** 필요한 것:

1. dev 에서 성능·안정성·안전성 3항목 통과
2. 원가 계측(CP-00A~C)으로 token 증가분의 실제 비용 확인
3. 사전등록한 holdout 캠페인에서 재확인

등록비는 운영 변동비(월 3,000원) 밖에서 따로 추적한다(D21). 그래도 **무제한이라는
뜻은 아니다** — 매장당 등록 1회 비용으로 환산해 보고한다.

## 실행 명령

```bash
# arm 마다 pdf_input_mode 를 바꿔 3회씩
PDF_INPUT_MODE=TEXT INGEST_MODE=real \
  python scripts/run_extract_eval.py --store store-a \
    --only-type SCAN --label PDF-TEXT-1
```

라벨 규칙: `PDF-<ARM>-<반복번호>`, A/A 대조군은 `PDF-TEXT-AA-<반복번호>`.
`compare_runs.py` 가 라벨 접두사로 실험군을 가르므로 **`PDF-TEXT-` 가
`PDF-TEXT-AA-` 를 삼키지 않도록** 반복 번호를 한정해 비교한다 (W0 에서 겪은 문제).

## 이 실험이 답하지 않는 것

- 영상·음성·카톡 입력에는 아무 말도 하지 않는다. SCAN 만 바꿨다
- 텍스트와 그림이 **다른 값**을 말할 때 무엇이 이기는지 정하지 않는다.
  BOTH 에서 모델이 알아서 고르며, 그 규칙은 W2(불변 revision·충돌 보존)의 몫이다
- 실제 점주 확인이 아니다. 정답지의 `owner_confirmed` 는 전부 `TEST` 다
