## 서버 먼저 필요한 기능 (계획 3, W 담당 서버 → 그다음 화면)

카드 상태 정의(2026-11-06 사용자): **공개**는 살아 있는 카드, **검수 필요**는 뭔가 이상한 카드, **미공개**는 공개하지 않는 카드, **삭제**는 DB 에는 남지만 사장님·알바생 누구도 어디서도 다시 볼 수 없는 카드(삭제 직후 5초 되돌리기만 있다). 화면은 지금 서버로 되는 만큼만 계획 3에서 만들고, 아래는 서버를 먼저 고친 뒤 붙인다.

- [ ] **공개 내리기(공개 → 미공개)** — 지금은 `exclude`(=삭제)만 있다. 공개된 카드를 공개 전 상태로 내리고 R 색인에서 빼는 API(예: `POST /cards/{id}/unpublish`, 공개 포인터 해제 + 재발행). 붙일 화면: 카드 목록 전체·공개 탭에서 왼쪽으로 밀기 → 미공개.
- [ ] **수정 되돌리기(이전 판으로)** — 사실 편집(`PUT /cards/{id}/facts`)을 바로 전 판으로 되돌리는 API. 붙일 화면: 수정 완료 스낵바의 '되돌리기'(5초). 그때까지는 "수정 완료" 토스트만.
- [ ] **검수 필요 카드를 공개하지 않고 미공개로** — `NEEDS_REVIEW → PENDING` 전환 API. 붙일 화면: 확인 필요 카드 상세의 공개 / 미공개 좌우 버튼(o07b) 중 '미공개'. 그때까지는 '공개'만.
- [ ] **충돌 값 고르기** — "역세척 3회 / 5회"처럼 두 값이 맞선 사실을 구조로 내려주는 응답. 붙일 화면: 확인 필요 사유 아래 라디오로 값 고르기(o07a).
- [ ] **되돌리기가 원래 상태로** — 위 '확인이 필요한 것'의 카드 되돌리기 항목과 같은 수정.

남은 [~] 두 줄(같은 문장 반복, 순서 블록 번호)은 **계획 6**(카드 조립 서버 고침, W)에서 끝낸다. 스펙 표에 올렸다.

- [x] **카드 타일 뒤 밀기 버튼이 비친다** (고침: SwipeRow 동작 버튼은 밀거나 포커스할 때만 보임, 점선 타일 배경 불투명. ui-cards '실화면 1') — 카드 목록에서 '공개'·'삭제' 글자와 초록·빨강 판이 타일 위로 보이고, 제목이 회색으로 겹친다. `SwipeRow` 의 동작 버튼은 늘 DOM 에 깔려 있는데 공개 전 타일(점선)은 배경이 투명이라 비친다. 밀지 않을 때는 동작 버튼을 숨기고(`opacity-0`, 밀거나 포커스할 때만 보임) 타일 배경을 불투명하게. 합성 테스트가 못 잡았다: 화면 캡처 비교가 없다.
- [x] **필터 칩 줄이 섹션 제목에 가려 잘린다** (고침: 가로 스크롤 줄에 shrink-0. 넣기 종류 칩도. ui-cards '실화면 2') — 카드 목록 위 칩(전체·공개·검수 필요·미공개)이 '음료제작' 제목에 덮인다. 칩 줄 높이·겹침(sticky/negative margin) 확인.
- [x] **작업 단계 이름** (고침) — '올렸어요 / 읽는 중 / 나누는 중' → **'올리는 중 / 읽는 중 / 카드 제작 중'**(파일 줄 상태 칩도 같게).
- [x] **'확인해 주세요' 사유가 코드로 보인다** (고침: web/lib/review-reason.ts, tests/review-reason.test.mjs) — `FACT_CONFLICT_OPEN` 같은 사유 코드를 사람 말로("같은 항목에 값이 두 가지예요: …"). 사유 코드 → 문구 표, 모르는 코드는 일반 문구.
- [~] **같은 문장이 값 개수만큼 반복된다** (화면만 고침: 보기 모드에서 같은 문장 한 줄로 묶고 값 모두 굵게, 여러 단계 줄은 굵게 안 함. 수정 모드·W 조립은 남음. 브라우저 테스트 없음 — 실자료로 눈 확인 필요) — 한 문장에서 값이 여러 개 나오면 사실이 값마다 나뉘어, 카드에 같은 문장이 값마다 한 줄씩(굵게만 다르게) 나온다. 제조순서 한 줄이 단계 5개로 5번 반복. 표시는 같은 문장(원문)을 한 줄로 묶고 값을 모두 굵게. 근본은 W 조립(사실 → 블록) 쪽: 한 문장에서 나온 단계들을 단계 블록에 문장 하나로 두거나 '→' 로 나눈 단계 글만 보이게.
- [~] **레몬에이드 '순서' 블록에 단계가 아닌 사실이 섞이고 번호가 1,1,1…** — 구분·금액·블랜더·컵 같은 값 사실이 STEPS 블록에 들어가 모두 1번. 단계(step_order 있는 제조순서)만 순서 블록, 나머지는 수치 블록. W 조립 규칙 수정(서버, W 담당) + 화면은 같은 번호 반복이면 번호를 숨긴다. (화면: 묶은 뒤 번호가 겹치면 그 블록 번호를 숨김. W 조립 규칙은 남음)
- [x] **정리 중인 작업이 오늘 매장에 안 보인다** (고침: components/owner/active-job-banner.tsx, ui-cards '실화면 3') — 자료를 올리고 뒤로 가면 진행 상태를 어디서도 못 본다. 오늘 매장 위에 '카드 제작 중' 진행 줄(누르면 작업 화면). 지금은 끝난 뒤 '정리 끝!' 배너만.

### 직원 화면·로그인 (계획 5)
- [ ] **'이전 대화 보기'로 불러온 옛 답이 한꺼번에 타이핑된다** — 처음 본 id 에 더 불러온 페이지 id 를 더하거나 마지막 답만 연출. 대화 목록 실패 후 재시도로 성공해도 같다.
- [ ] **타이핑이 화면낭독기에서 조각으로 읽힐 수 있다** — 보이는 글은 `aria-hidden`, 전체는 sr-only 하나로.
- [ ] **묶은 줄의 조건·예외가 어느 값 것인지 사라진다** — 값 옆에 붙이기. `withValues` 가 단위 없는 값으로 '12시'의 '2'를 굵게 할 수 있다(기존).
- [ ] **밀기 판이 놓은 순간 사라져 빈 바탕이 번쩍인다** — 투명도에도 같은 전환, 또는 이동이 끝난 뒤 숨기기.
- [ ] **레시피 시트를 닫으면 닫히는 동안 제목·내용이 빈다** — 닫힘 애니메이션 동안 마지막 미리 보기 유지.
- [ ] **제출 실패 뒤 '더 체크하기'로 닫고 다시 열면 옛 오류가 남는다** — 열기·취소 때 `submit.reset()`.
- [ ] **세션 없는 `/staff/ask` 알림(v1)은 눌러도 읽음만 되고 이동이 없다** — 세션이 없으면 `/staff/ask` 로.
- [ ] **읽은 알림 `opacity-60` 로 회색 본문 대비가 AA 아래일 수 있다.**
- [ ] **추천 칩 key 가 질문 글이라 같은 질문이 여러 카드에 있으면 겹친다** — 질문으로 중복 제거.
- [ ] **끝난 단계가 '올리는 중 ✓'처럼 진행형으로 체크된다** — 사용자 지정 이름이라 둠. 끝난 단계만 과거형으로 바꿀지 결정 필요.
- [ ] **작업 중 배너와 '정리 끝!' 배너가 함께 쌓일 수 있다**(서로 다른 작업).
- [ ] **ui-nav 'BackButton 보조 키 클릭'이 가끔 새 탭 대기 5초를 넘는다.**
- [ ] **테스트 빈 곳** — 타이핑 중 다음 질문 전송, 레시피 시트 실패 뒤 체크 유지.
- [ ] **확인 필요(판단)**: 근무조 칩을 없애 다른 근무조를 대신 서는 직원이 그 목록을 못 본다(서버 '자기 근무조' 기준 확인). 직원 레시피에서 '인용 끊김'을 뺀 것이 D20('UI 인용 끊김 표시')과 맞는지. 추천 칩이 오늘·레시피에선 채우기, 버디에선 바로 보내기로 다른 것이 의도인지. '새 답' 점이 알림을 읽어야만 꺼지는 것(대화에서 답을 봐도 남음).
