- [ ] **질문 알림 함수의 안 쓰는 인자** (계획 1) — `api/app/notifications/service.py` 의 `create_pending_question_notification(..., contract_version=...)` 는 이제 목적지를 만들 때 이 값을 쓰지 않는다. 호출하는 쪽이 아직 넘기고 있어 남겨 뒀다. R 담당과 맞춰 지운다.

## 서버 먼저 필요한 기능 (계획 3, W 담당 서버 → 그다음 화면)

카드 상태 정의(2026-11-06 사용자): **공개**는 살아 있는 카드, **검수 필요**는 뭔가 이상한 카드, **미공개**는 공개하지 않는 카드, **삭제**는 DB 에는 남지만 사장님·알바생 누구도 어디서도 다시 볼 수 없는 카드(삭제 직후 5초 되돌리기만 있다). 화면은 지금 서버로 되는 만큼만 계획 3에서 만들고, 아래는 서버를 먼저 고친 뒤 붙인다.

- [ ] **공개 내리기(공개 → 미공개)** — 지금은 `exclude`(=삭제)만 있다. 공개된 카드를 공개 전 상태로 내리고 R 색인에서 빼는 API(예: `POST /cards/{id}/unpublish`, 공개 포인터 해제 + 재발행). 붙일 화면: 카드 목록 전체·공개 탭에서 왼쪽으로 밀기 → 미공개.
- [ ] **수정 되돌리기(이전 판으로)** — 사실 편집(`PUT /cards/{id}/facts`)을 바로 전 판으로 되돌리는 API. 붙일 화면: 수정 완료 스낵바의 '되돌리기'(5초). 그때까지는 "수정 완료" 토스트만.
- [ ] **검수 필요 카드를 공개하지 않고 미공개로** — `NEEDS_REVIEW → PENDING` 전환 API. 붙일 화면: 확인 필요 카드 상세의 공개 / 미공개 좌우 버튼(o07b) 중 '미공개'. 그때까지는 '공개'만.
- [ ] **충돌 값 고르기** — "역세척 3회 / 5회"처럼 두 값이 맞선 사실을 구조로 내려주는 응답. 붙일 화면: 확인 필요 사유 아래 라디오로 값 고르기(o07a).
- [ ] **되돌리기가 원래 상태로** — 위 '확인이 필요한 것'의 카드 되돌리기 항목과 같은 수정.

### 카드 (계획 3)
- [ ] **상세에서 삭제 되돌리기 실패가 안 보인다** — 마지막 사실을 빼서 카드가 삭제된 뒤 '되돌리기'가 실패하면 삭제 안내 화면이라 오류가 안 보인다. 목록처럼 "되돌리지 못했어요" + '다시' 스낵바.
- [ ] **검수 필요 뱃지가 삭제된 카드에 걸린 제안도 센다** — 제안 응답에 대상 카드 상태가 없다. 서버가 상태를 주거나 합친 수를 주면 정확해진다(서버).
- [ ] **처음 여는 카드는 최대 0.6초 멈춘 듯 보인다** — `lib/shared-title.ts` 가 상세 제목을 기다린다. 타일을 누를 때 상세 조회를 미리 받아 두면(`prefetchQuery`) 대부분 사라진다.
- [ ] **손잡이 이름이 겹칠 수 있다** — 문장 앞 12자라 메뉴 이름으로 시작하는 줄끼리 같아진다. 순서 번호와 문장 전체로. 카테고리 칩 이름은 "카테고리 바꾸기"로(손잡이와 끝말이 같다).
- [ ] **스크린리더가 '다른 답이 있어요'를 못 읽는다** — 타일 `aria-label` 이 내용을 덮는다. 제안이 있으면 이름표에 붙인다.
- [ ] **만들어 낸 제안 타일이 카테고리 필터를 무시하고, 늘 '공개'로 친다** — 삭제된 카드에 걸린 제안이면 삭제 카드가 보일 수 있다.
- [ ] **값 굵게가 엉뚱한 숫자에 붙을 수 있다** — "2번째 컵에 시럽 2펌프"에서 첫 2. 값+단위를 먼저, 없으면 마지막 것.
- [ ] **수정 중 뒤로 가기는 버릴지 묻지 않는다** — '돌아가기'만 묻는다. 수정 중엔 뒤로 버튼도 묻거나 숨긴다.
- [ ] **제안 비교가 다 바뀐 글에서는 지저분하다** — 공백까지 같은 것으로 잡혀 지운 것·넣은 것이 번갈아 나온다.
- [ ] **제안 버튼을 눌러도 화면에 머문다** — '수정하지 않고 돌아가기'는 제안을 닫는(영구) 동작인데 이름은 이동처럼 들린다. 누른 뒤 목록으로 돌아가고, 이름을 맞춘다.
- [ ] **근무조 스위치 묶음에 이름이 없다** — `role="group"` 과 제목 연결.
- [ ] **카드 목록 두 칸/한 칸을 카테고리 이름으로 가른다** — 레시피 카테고리만 두 칸(2026-11-07 스케치). 카테고리에 종류(레시피/공지/위치…)가 없어 이름에 '레시피·음료·메뉴·제조·제작'이 들어가면 두 칸으로 본다. 서버 카테고리 종류가 생기면 그걸로 바꾼다(서버).
- [ ] **공개 밀기를 연달아 하면 두 번 보낼 수 있다** — 첫 요청이 끝날 때까지 그 카드 밀기를 막는다.

### 오늘 매장·질문 (계획 4a)
- [ ] **질문 목록의 '몇 번 물어봤어요'** — 목록 응답(`/learn/v2/pending`)에 물어본 횟수가 없다. 상세에서만 보인다(서버).
- [ ] **근무조 줄을 누르면 그 근무조 현황으로 커지는 전환(o01b)** — 근무조별 체크 현황 화면이 없다. 화면부터 만들어야 한다.
- [ ] **탭 알약이 실제로는 미끄러지지 않는다** — 화면마다 탭바를 새로 그려 스프링 이동이 안 보인다. 탭바를 레이아웃으로 올리거나 이전 위치에서 시작하게. 활성 탭이 없으면 알약을 숨긴다.
- [ ] **'답을 보냈어요'에서 다음 질문으로 갈 때 앞 질문 화면이 잠깐 비친다** — `router.replace` 뒤 `setSent(false)` 를 빼면 된다(새 주소면 화면이 다시 그려진다).
- [ ] **답 첨부 종류 칩이 이미 붙인 파일을 분류하는 것처럼 보인다** — 칩은 다음에 붙일 파일부터 쓴다. "다음에 붙일 파일 종류"로 말하거나 올리기 전에 칩을 보인다.
- [ ] **질문이 하나뿐일 때 '나중에'를 눌러도 아무 변화가 없다** — 짧은 토스트. 줄마다 '나중에' 버튼 이름이 같아 스크린리더에서 어느 질문인지 모른다.
- [ ] **세그먼트가 탭 역할만 있고 탭 동작이 없다** — tabpanel 연결·화살표 키가 없다. `aria-pressed` 버튼으로 바꾸거나 연결한다. 탭·세그먼트 안 숫자 뱃지는 "검수 필요 2"처럼 읽히게.
- [ ] **'물어본 말 보기' 버튼에 포커스 테두리가 없다.**
- [ ] **테스트 빈 곳** — 입력창이 숨은 채 시트 열기, 질문 하나일 때 나중에(포인터 밀기), 다음 질문으로 간 뒤 새 입력창인지.
