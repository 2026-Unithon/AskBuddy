# 화면 개선 계획 6: 카드 조립 고침 (기록)

**배경(2026-11-07 사용자 실화면 지적):** 한 문장이 값마다 쪼개져 같은 문장이 반복되고(제조순서 5번), 메뉴 표의 칸(구분·금액·컵…)에 단계 1이 붙어 '순서' 블록에 섞여 번호가 1,1,1 로 나왔다.

**원인:** 추출 프롬프트(`api/prompts/extract_facts.ko.txt`, `extract_facts_locator.ko.txt`)
- 규칙 1 이 `original_assertion` 에 "자료 문장 그대로"만 요구해 한 문장에서 뽑은 사실들이 모두 같은 문장을 가졌다(서버는 `assertion` 을 이 값으로 복사한다).
- 규칙 7 이 `order` 를 "순서가 의미인 절차"로만 적어 표의 칸·값 나열에도 번호가 붙었다. 조립은 번호가 있으면 무조건 STEPS 블록에 넣는다.

## 바꾼 것

| 층 | 파일 | 내용 |
|---|---|---|
| 프롬프트 | `extract_facts.ko.txt`, `extract_facts_locator.ko.txt` | 규칙 1: 한 문장에서 여러 사실이면 그 사실 부분만 옮긴다(예시 포함). 규칙 7: 단계가 아닌 사실(표의 칸, 값 나열, 행 번호)에는 `order` 를 쓰지 않는다 |
| 조립(서버) | `api/app/ingest/card_plan.py` `normalize_step_orders`, `fact_assembly.py` | 번호를 단계로 인정: 문장에 `→` 가 있거나 같은 규격에서 그 번호를 혼자 쓸 때. 버림: 다른 문장과 같은 번호를 나눠 씀(표 칸마다 1번), `→` 없는 한 문장에서 번호 여러 개. 저장 판은 그대로, 조립·렌더용 사본만 |
| 본문(서버) | `card_plan.render_card` | 같은 블록의 같은 줄은 한 번만(`render_missing` 은 포함 여부라 그대로 통과) |
| 화면 | `web/components/owner/fact-card/fact-group.ts`, `fact-row.tsx` | 이미 만든 카드도 같게: 값 사실은 같은 문장을 한 줄로, `→` 단계 문장은 이름 + 1·2·3 줄로 펼침, 진짜 단계일 때만 번호 |
