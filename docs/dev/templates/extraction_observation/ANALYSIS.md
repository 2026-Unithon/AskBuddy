# 관찰 분석 양식 — "평균적인 처리 순서" 뽑기

> 한 로직(필요하면 로직 × 형식)마다 하나. 실행이 3개 이상 모였을 때 쓴다. 결과 문서는 `docs/dev/review/OBSERVATION_<LOGIC>_<YYYYMMDD>.md`.
> 예전 레시피 관찰의 결론이 SCAN 다단계 설계(`docs/dev/plan/W_SCAN_LAYOUT_EXTRACTION_DESIGN.md`)가 된 과정을 일반화한 양식이다.
> 외부 실행끼리의 일치는 **정답이 아니다**(`docs/dev/plan/W_REFERENCE_EXTRACTION_20260920.md` 역할 한계). 자료 이름은 익명 id 만.

## 1. 대상
- 로직 / 형식 / 자료 id 목록(분량: 쪽·길이·메시지 수)
- 실행 목록: RUN_SHEET 의 실행 id 들

## 2. 단계 정렬표
실행마다 작업 기록(1부)의 단계를 같은 종류끼리 한 줄에 맞춘다. 칸에는 그 실행의 단계 번호와 짧은 메모.

| 단계 종류 | C1 | C2 | G1 | G2 | 한 실행 수 | 비고 |
|---|---|---|---|---|---|---|
| 원본 훑기(눈으로) | 1 | 1 | 1 | 1 | 4/4 | |
| 글자 층·구조 추출 | 2 | — | 2 | 3 | 3/4 | |
| 영역 자르기·확대 | 4 (띠 4×2, 2.2배) | — | 3 | — | 2/4 | 확대한 실행만 값이 수렴 |
| 행 단위 전사 | … | | | | | |
| 코드로 사실 펼치기 | … | | | | | |
| 재검증(표본 대조) | … | | | | | |

- **공통 단계**: 과반 실행이 한 단계.
- **갈린 단계**: 일부만 한 단계와, 한 실행과 안 한 실행의 결과 차이.
