## 이번 추가 구현의 정확한 범위

**제품 연결:** 검토된 제안이라도 매장, 질문, 후속 문맥, 확정 슬롯, 승인판, 검색 후보가 다르면 채택하지 않는다. 서버가 참조·필수 근거·조건·예외·현재 발행판·권한을 검사한 뒤 기존 답변 renderer와 저장을 사용한다. 검토 파일은 별도 hash로 고정하고 승인 이력을 기록한다. 실제 검토 파일 설치나 운영 활성화는 하지 않았다.

**평가 예산:** 의미 제안 생성 실행기는 최대 금액·호출 수·토큰·단가 상한·대상 run·만료시각을 명시한 정책이 있어야 호출한다. DB에서 최대 비용을 먼저 예약하고 동시 실행·재시작·중복 요청·정책 변경을 통제한다. 실패/크래시 비용도 환불하지 않고, 사용량 결측·토큰 초과는 캠페인을 정지한다. 금액 제한은 승인 단가 상한과 공급자의 토큰 제한 준수를 전제로 한다.

**추가 R 구현이 남은 범위:** embedding/reranker까지 포함한 전체 HTTP 유료 평가에는 단계별 예산 어댑터와 총예산 배분 연결이 더 필요하다. 현재 생성 실행기의 예산 구현만으로 전체 평가 비용 제한이 완성됐다고 보고하지 않는다. 처음 보는 자유 표현의 실시간 일반화 경로도 현재의 정확한 검토 입력 연결과 구분해 설계·평가해야 한다.

## 회의 후 진행 순서

1. 담당·일정·정답 검토 방식과 예산을 문서로 확정한다. 대기 해제와 실제 실행 지시는 명시적으로 남긴다.
2. 사람 정답과 W 승인 snapshot을 연결한다. 일반화 제품 범위와 전체 평가의 추가 예산 구현 범위를 확정한다.
3. 해당 추가 구현을 검증한 뒤 승인 범위에서 격리 평가를 실행한다. 실패·미판정·비용 결측을 제외하지 않는다.
4. 품질·안전·비용 기준 통과 여부를 판정하고 W 공동 종단 인수를 수행한다.
5. 통과한 범위만 활성화하고 철회·복구를 확인한다.

현재 상태는 **R 기반 구현 및 합성 회귀 완료, 추가 일반화/통합 예산 구현과 실제 품질·공동 인수 미완료**다. “R 전체 완료”나 “출시 준비 완료”로 공유하지 않는다.
