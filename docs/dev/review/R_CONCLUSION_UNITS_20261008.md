# R 결론 문장 선택·미확인 사건 조건 검사 — 2026-10-08

직전 실제 Gemini 평가에서는 근거별 제안은 통과했지만 검증기가 승인 원문을 결론 인용에 넣어 답변이 거절됐다. 미전달 환불 결론에 사용자가 주지 않은 금액·결제일을 승인 사유처럼 표현한 위험도 있었다. 이번에는 두 문제를 보완하고 로컬 회귀·실제 API/DB 검증을 완료했다. **추가 유료 호출은 0회이며 실제 모델의 정확도 개선을 확인한 결과는 아니다.**

## 변경

- 일반 의미 v11. 서버가 결론 문장을 원문 위치 그대로 나누어 `c0s0` 같은 요청 내 ID를 붙인다. 문장 표는 검증 request_hash에 묶인다. 소수점·문장 내부 절을 임의로 다시 쓰지 않는다.
- 검증기의 `rule_coverage`는 `conclusion_unit_id`를 선택한다. 서버는 존재하는 문장인지, 그 결론이 해당 승인 규칙을 인용하는지 검사한다. 필수 규칙에 적용 문장이 없으면 기존 INCOMPLETE_ANSWER로 거절한다. 옛 `conclusion_id/conclusion_quote` 필드는 신규 모델 계약에서 제거했고 옛 출력 자동 변환은 없다.
- `situation_review`는 모든 문장을 한 번씩 검토한다. 일반/명시적 조건부 안내(NO_CASE_FACTS), 사용자 출처로 뒷받침된 사건 사실(GROUNDED_CASE_FACTS), 미확인 사실 단정(UNSUPPORTED_CASE_FACTS)을 구분한다. 근거를 주장할 때 실제 사용자 발화와 해당 결론의 사용자 인용에 결속해야 한다. 누락·중복·임의 ID·위조 인용은 거절한다.
- 미확인 사건 조건 판정은 `supported=true`와 함께 와도 CONTEXT_CONFLICT로 거절하며 정상 답변·receipt·점주 대기를 만들지 않는다. 승인 대기라는 상태에서 금액·날짜·승인 사유를 역으로 추정하지 말도록 제안/검증 프롬프트도 보완했다.
- 알려진 상태만으로 답할 수 있으면 추가 조건을 요구하지 않는다. 일반 조건부 설명은 실제 사건 사실 단정과 구분하며, 필요한 재질문과 기존 사건 선택 후속 흐름은 유지한다.

문장 선택의 의미 적합성, NO_CASE_FACTS 분류, 사용자 발화가 주장 전체를 함의하는지, 최신 정정 여부는 여전히 모델 판단이다. 예를 들어 검증기가 미확인 사실을 잘못 GROUNDED로 분류하면 문자열 검사만으로 모두 막을 수 없다. 이번 변경은 명시적 검토·출처·거절 계약 보강이며 사실성 보장이 아니다.

두 모델 호출 구조, 기본 OFF, 공개 API/DB schema, 과거 저장 답변은 유지했다. 새로운 source hash 인수가 필요하며 기존 유료 평가 release로 새 소스를 실행할 수 없다. DB migration 추가 없음. 승인 정책을 수정하거나 모델 제안을 사후 교정하지 않았다.

실제 출력은 `api/tests/fixtures/r_conclusion_units_live_20261008.json`에 변경 없이 보존했다. 새 계약의 검증 응답 및 금액·날짜 단정을 제거한 양성 결론은 **합성 테스트**다. 과거 실제 실패를 성공으로 재채점하지 않았다.
