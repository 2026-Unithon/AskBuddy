# R 단독 후속 — 승인 원문 조회·평가 원가 분리

2026-09-16. 선행 묶음은 [R_SOLO_EVALUATION_AND_ACCESS_20260916.md](R_SOLO_EVALUATION_AND_ACCESS_20260916.md). 사용자는 실자료가 아직 없으며 확인 후 알려주겠다고 답했고, 가능한 다른 작업을 계속하도록 요청했다. 실자료 인수는 대기하며 합성 자료를 실자료 정답으로 승격하지 않는다.

## 추가 구현

### 명시적인 승인 RAW 원문 조회

planner `r-explicit-slots/v2`에서 **정확한 카드 제목 + ‘승인 원문 보여줘/보여주세요/보기’**만 지원한다. 전체 문장이 이 패턴과 일치하고, 명시 대상이 한 entity이며, 해당 카드의 모든 RAW 블록이 현재 검색 후보에 있어야 한다. 서버는 요청 원문 hash·매장·snapshot/revision/hash·정확한 RAW 참조에 묶인 suitability assessment를 만든다. 기존 공통/R 검증과 저장 검증을 그대로 통과해야 응답한다.

- RAW 본문/출처를 그대로 렌더하고 정확한 인용을 저장한다.
- 업무 적용 범위·수량·절차를 RAW에서 자유 추론하지 않는다.
- 문맥 추정과 결합하지 않으며, 미회수 RAW를 snapshot에서 무조건 꺼내지 않는다.
- 정책 질문과 변경 요청은 기존 분기가 우선한다.
- 일반 질문에 대한 RAW 충분성 및 복합 절차 의미 판정 전체를 구현한 것은 아니다.

### 평가 원가 sink

`app.team.evaluation_usage.EvaluationUsageSink(sink, store_id=..., evaluation_run_id=...)`를 격리 평가 하네스에서 명시적으로 주입한다. 비용 phase와 논리 호출/operation ID를 유지하면서 purpose를 `EVALUATION`으로 연결한다. 다른 매장/평가 실행 및 start하지 않은 finalize를 거절한다. 원본 UsageAttempt를 수정하지 않는다.

실제 DB에 존재하는 evaluation_run_id와 durable sink를 호출자가 제공해야 한다. 제품 라우트의 전역 계측 설정을 바꾸지 않았으며, 도구를 만들었다는 이유로 이미 실행한 모든 평가가 올바르게 귀속됐다고 주장하지 않는다. 실제 유료 호출은 수행하지 않았다.

## 검증

- 전체 단위 **582 tests / 119 subtests 통과**, 기존 의존성 경고 1개.
- RAW 관련 새 5개 테스트: 정확한 원문/인용, 다른 질문으로 assessment 재사용 거절, 자유 질문/변경/정책 혼합 거절, 미회수 원문 거절.
- 원가 어댑터 2개 테스트: 원본 PRODUCT 유지와 기록 EVALUATION 분리, 다른 매장/미시작 finalize 거절.
- 실제 DB/API에서 승인 RAW 응답 확인. 새 요청 추가로 기존 재시도 테스트의 `전체 호출 횟수 == 1` 가정이 깨져, **재시도 직전/직후 호출 횟수 동일** 검사로 수정했다. 제품 재시도 동작은 변경하지 않았다.
- PostgreSQL 17.11, 26 migration 재구축 및 M2 40 / reranker 13 / 답변 저장 16 / v2 API 94 / 점주 전달 21과 선행 원가·보안·W·문맥 검사 통과. 다회 평가도 통과.
- 마지막 원가 어댑터 추가는 별도 단위 검증이며 실제 DB purpose 귀속은 후속 실평가 연결 때 확인해야 한다.
- 변경 영역 26개 파일 매장 격리 정적 검사 및 diff 검사 통과. 검증 컨테이너 정리 완료.

## 현재 남은 경계

실자료 없이도 가능한 평가/권한/관측 코드와 명시적 RAW 조회를 보완했다. R 전체 완료는 아니다. 특히 일반 RAW·복합 조건의 적용성 판단, 의미 동치 자동 묶음, 실자료 사전/hybrid/reranker 효과·비용·p95 검증, W 실제 발행과 FAQ/학습 갱신 공동 인수는 남아 있다. 실자료를 받으면 새 평가 도구로 실패 원인을 분리한 뒤 후속 런타임 확장을 검토한다. 기본 v2/reranker rollout 설정은 바꾸지 않았다.
