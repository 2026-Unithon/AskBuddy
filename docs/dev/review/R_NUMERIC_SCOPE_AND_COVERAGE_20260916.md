# R 수치 적용 범위·모순 조건·검토 초안 확충

2026-09-16. R2/R3/R4 적용 범위와 R0/R5 검토 자료 준비를 진행했다. Docker·W 구현·외부 모델·운영 배포 없이 수행했다. 과거 review와 실자료 원본은 변경하지 않았다.

## 구현

### 수치 조건의 포함 관계

`learn/numeric_scope.py`에 Decimal 기반 구간 연산을 추가했다. 같은 속성·같은 단위에서만 교집합·부분집합·배타성을 판정한다. 단위를 추정하거나 자동 환산하지 않는다.

- 승인 조건 `온도 60도 이상`에 질문 `온도 70도인 경우`가 포함되는지 판단한다.
- 이상/초과/이하/미만의 열린·닫힌 경계를 구분한다. `60도 초과`에 `60도인 경우`는 포함되지 않는다.
- `온도 60도 이상 80도 미만`처럼 하한·상한이 있는 범위를 지원한다. 질문 범위 전체가 승인 조건 안에 있어야 한다. `65도 이상`처럼 상한을 벗어날 수 있는 질문은 통과하지 않는다.
- 실제 측정 완료를 추정하지 않는다. 사용자 질문이 명시한 가정 범위를 판정하며 승인된 원래 조건은 답변에 그대로 보존한다.
- 지원 단위는 도/ml/l/g/kg/개/분, 값은 제한된 비음수 십진수 문법이다. 다른 단위·속성, 지수 표기, 임의 수식은 수치 추론 대상이 아니다. 온도 음수 등 추가 문법을 일반화했다고 주장하지 않는다.

`conditional_scope.py`에서 승인 조건 전체 대조에 위 판정을 연결했다. 숫자를 포함한 예외 전체나 임의 중첩 논리를 해석하는 구현은 아니다.

### 모순 조건 차단

- 하한이 상한보다 큰 승인 구간이나 동일 경계의 빈 열린 구간은 거절한다.
- 함께 제시한 조건의 수치 구간이 겹치지 않거나 같은 조건의 긍정/부정이면 답변을 허용하지 않는다.
- 같은 승인 조건이라도 `70도인 경우`와 `71도인 경우`는 실제 질문 범위를 의미키에 보존해 서로 다른 pending으로 둔다.
- planner 버전은 `r-explicit-slots/v7`, 의미키 버전은 `r-explicit-question/v4`다. 기존 pending을 재작성하거나 자동 병합하지 않는다. 평가 source hash에 신규 수치 판정 모듈을 포함한다.

### 실자료 질문 초안

- `review_queue.py` 기본값을 20→40으로 늘렸다. 전체 초안 수와 서로 다른 질문 문구 수를 따로 보고한다. 숫자만 늘려 커버리지 달성으로 표시하지 않는다.
- RAW 근거 검토 필드도 초안에 명시적으로 남기고, 사람 판정 필드는 null을 유지한다.
- `scripts/prepare_r_review_queue.py`는 dev 두 매장만 지원한다. source review와 queue는 내용 hash별 배타 생성하며 같은 입력 재실행은 동일 산출물을 확인하고 재사용한다. 과거 20문항 queue를 덮어쓰지 않는다.
- 실제 실행 결과: **두 매장 각각 40개 초안 / 서로 다른 질문 문구 37개 / 검토 완료 0개**. snapshot별 정답 질문 30~50문항 완료를 뜻하지 않는다. 의미가 같은 다른 문구도 있을 수 있다.
- 새 산출물은 기존 Git 제외 `api/eval/data/<dev store>/r-review/` 안에 저장했다. 원문·실제 메뉴명·질문 내용은 콘솔이나 이 문서에 기록하지 않았다. holdout은 읽지 않았다.

## 검증

- 전체 **735 passed / 119 subtests passed**, 기존 Starlette/AnyIO deprecation warning 1건.
- 수치 경계/열린 구간/다른 단위/다른 속성/과도한 질문 범위/모순 조건/원래 조건 렌더/묶음 분리 반례 통과.
- 작은 정수 경계와 반 단위 표본의 독립 집합 연산을 기준으로 구간 교집합·포함 판정을 전수 대조했다. 임의 실수 전체에 대한 형식 증명은 아니다.
- 변경 app 7파일 매장 격리 AST 위반 0건. 신규 CLI 구문 검사와 `git diff --check` 통과.

- Docker DB·실제 W 발행·실자료 의미 성능 평가는 실행하지 않았다.

## 잔여
