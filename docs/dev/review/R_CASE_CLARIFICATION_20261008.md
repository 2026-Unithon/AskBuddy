# R 사건 선택과 후속 대화 연결

2026-10-08. 실제 Gemini 소수 평가의 OD06-2는 “A/B 중 그 건”의 모호함을 감지했지만 기존 entity/temperature/size 계약으로 사건을 물을 수 없어 점주 전달로 끝났다. 이번에는 `case` 선택형 명확화와 선택 이후 사용자 원문 복원을 구현했다. 실제 Gemini 재평가는 이번 작업에 포함하지 않았다.

## 동작

1. 사용자가 “A는 결제 상태 미확인, B는 환불 승인 대기”라고 설명한다.
2. “그 건은 메시지 읽었대. 인계 완료로 해도 돼?”에서 모델이 사건 명확화를 제안하거나 검증기가 필요성을 제시한다.
3. 서버가 A/B 표시명, 해당 사용자 발화의 순서, 정확한 원문 인용을 검사한다. 선택지는 2~10개이며 중복·위조·순서 불일치·이미 확정된 사건을 다시 묻는 제안은 거절한다. A를 APP의 일부에서 가져오는 경우도 막는다.
4. `CLARIFY`와 “어느 건을 말씀하시는지 선택해 주세요.”, A/B 버튼을 반환한다. 사건 선택은 pending이나 점주 알림을 만들지 않는다.
5. 사용자가 A를 선택하면 서버의 기존 소유권·TTL·문맥 revision·허용 선택지 검사를 거친다. `confirmed_slots.case=A`만 확정하며 A의 상태나 B의 조건을 바꾸지 않는다.
6. 선택 이후에도 최초 사건 설명을 검색·일반 의미 제안·검증에 전달한다. 매장 정책용 기본 planner나 exact-reviewed 어댑터가 개별 사건을 해석한 것으로 간주하지 않고 일반 의미 검증 경로를 사용한다.

모델의 사건 의미 구분과 선택지 완전성은 독립 검증·평가 대상이다. 원문 일치와 유효한 사용자 턴 참조만으로 의미 정답을 보장하지 않는다.

## 저장·호환

- 외부 AnswerPlan의 `clarification_slot`은 이미 문자열이고 기존 직원 UI는 `allowed_options`를 버튼으로 렌더링하므로 새 enum이나 프론트 구조 변경 없이 동작한다.
- 기존 `r_question_contexts.proposed_slots`의 서버 전용 `_case_dialogue`에 사용자 원문과 사건 선택 근거를 보존한다. 이 항목은 모델 추정 슬롯이 아니라 서버 입력에서 가져온 사용자 문맥이다. 모델이 임의 context ID를 발행하거나 해당 내부 필드를 HTTP로 제출하는 경로는 없다.
- 공개 지식 revision이 바뀌면 모델 제안은 폐기하지만 사용자 사건 원문은 유지하고 새 승인판을 다시 검색한다. 일반 사건 상태 DB나 금액·날짜의 구조화 저장을 도입한 것은 아니다.
- 첫 명확화와 두 번째 명확화 모두 사건 원문을 저장할 수 있다. 명확화 최대 2턴, 기존 요청 멱등성·세션 권한을 유지한다.
- 일반 의미 내부 버전은 v5다. 소스·프롬프트 hash가 바뀌므로 이전 평가 release를 재사용할 수 없다. 운영 기본 OFF는 유지한다.

## 검증

- 전체 단위: **1,827 passed, 4 xfailed, 131 subtests passed**. 기존 Starlette 경고 1건. `api/tmp/r-case-full-01.log`.
- 신규 사건 명확화 회귀 10개: 검증기 fallback, 제안 직접 명확화, 원문 보존, 공개판 변경 시 사용자 문맥 보존, 위조/중복/임의 선택지/잘못된 턴/이미 확정된 사건 차단, 2턴 제한.
- PostgreSQL 17의 41개 migration과 전체 API/DB suite 통과. 추가 사건 세션 격리 검사 포함 `api/tmp/r-case-pg17-02.log`.
- 실제 HTTP에서 사건 원문→A/B 명확화→A 선택→검증된 답변 저장, 이전 사건 발화 전달, pending 증가 없음, 같은 요청 재전송 시 공급자 재호출 없음, 오래된 revision·임의 C 선택 422, 다른 세션의 context 사용 404를 확인했다. 모델 응답은 합성으로 고정했다.
- `store-isolation-check` AST 검사: `api/app/learn` 36개 파일, 위반 없음. 전체 통합 suite의 다른 매장·회원 문맥 격리 회귀도 통과.
- 유료 AI 호출 0회. 운영 DB·외부 알림 변경 없음.

## 남은 작업

이번 결과는 사건 선택 경로의 구조·저장·권한 검증이다. 실제 Gemini가 새 case schema를 안정적으로 출력하고 올바른 사건을 구분하는지는 소규모 유료 재평가가 필요하다. 이전 유료 결과를 이번 변경의 성능으로 재사용하지 않는다.

상황별 결론 렌더링과 필수 근거 누락 검증, 5초 지연 인수는 남아 있다. 다음 단계에서는 선택 후 현재 사건의 조건과 승인 규정의 적용 근거를 연결하는 AnswerPlan 확장을 먼저 설계·검증한다. 원문 규정 전체를 반복한 답변을 완결 답변으로 승격하지 않는다.
