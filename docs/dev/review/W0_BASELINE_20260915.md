그때는 이 문서를 고치지 않고 새 기록을 남긴다.

## 2. 측정 도구에서 찾은 결함

정답지는 문제가 없었다. 결함은 전부 하네스에 있었다.

| 결함 | 증상 | 조치 |
|---|---|---|
| 계측이 추출을 죽임 | 논리 호출 ID 에 실행 범위가 없어 같은 자료의 두 번째 추출이 원장 unique 에 걸려 전멸 | 키에 run/job 범위 추가 |
| 빈 실행이 `SUCCEEDED` | 자료 5건 전부 실패·카드 0장·손실 100% 가 측정값으로 기록되고, 그 빈 실행 둘을 비교한 결과가 "차이 없음" | 판정을 순수 함수로 분리하고 전멸이면 멈춤. 일부 실패는 `PARTIAL` |
| 실험군이 서로를 삼킴 | `label like 'BASE-%'` 가 대조군 `BASE-AA` 까지 포함 | 반복 번호만 묶도록 한정 |
| 분모가 교집합 | 한쪽에서 사라진 사실이 조용히 빠짐 | 정답지 전체로 고정 |
| 실패한 실행을 안 셈 | 절반씩 깨지는 설정이 멀쩡해 보임 | 실패 횟수·실패율 보고 |
| precision 미측정 | 정답지만 순회해 재현율만 보임 — 쓰레기를 500건 뱉어도 점수가 같음 | 출력 쪽 채점 추가 |

이미 잘못 기록된 실행은 프리즈 트리거가 지켜 고쳐 쓰지 않았다. 집계에서만 제외한다.

## 3. 기준선

같은 설정을 3회씩 두 묶음(BASE·BASE-AA). 두 묶음의 차이가 잡음 바닥이다.

| 매장 | 손실 | 폭 | 입력 토큰 | 출력 토큰 |
|---|---|---|---|---|
| A (132건) | 77.3 · 78.0 · 79.5 · 79.5 · 79.5 · 82.6 % | 5.3%p | 36,138 (6회 동일) | 4,988~8,185 |
| B (48건) | 25.0 · 27.1 · 29.2 · 41.7 · 41.7 · 41.7 % | 16.7%p | 28,084 (6회 동일) | 5,869~8,629 |

**입력은 6회 모두 바이트 단위로 같은데 출력이 흔들린다.** 추출 온도 0.0(D16)은
변동을 줄였을 뿐 없애지 않았다.

정답이 132건인 A 의 폭이 48건인 B 보다 좁다. 사실 1건이 A 는 0.76%p, B 는 2.1%p 라
분모가 클수록 눈금이 촘촘하다.

### A/A 대조

| 기준 | A 매장 | B 매장 |
|---|---|---|
| 만장일치 순증 | 0건 | 0건 |
| 다수결 순증 | +1건 (개선 12·악화 11) | −4건 (개선 3·악화 7) |
| 흔들림 | 64/132 (48%) | 16/48 (33%) |
| must_have 흔들림 | 54/113 | 11/37 |

**다수결로 뒤집힌 것이 만장일치로는 전부 0이었다.** 2:1 과 1:2 가 맞붙은 것이고,
아무것도 바꾸지 않았는데 "A 가 낫다" 라는 판정이 나왔다.

### 유형별 (A 매장, BASE#1)

| 유형 | 정답 | 담김 | 손실 |
|---|---:|---:|---:|
| VIDEO | 62 | 2 | 96.8% |
| SCAN | 57 | 16 | 71.9% |
| VOICE | 6 | 1 | 83.3% |
| KAKAO | 7 | 4 | 42.9% |

`loss_stage`: EXTRACTION 102 · ASSEMBLY 7 · CARD_ONLY 5 · OK 18.

다만 **이 시점의 EXTRACTION/ASSEMBLY 구분은 믿을 수 없다.** 당시 원장은 최종 카드에서
거꾸로 기록됐으므로, 조립 중에 버려진 사실은 원장에 남지 않아 EXTRACTION 으로 분류된다.
구조를 고친 뒤 다시 재야 한다.

과거 문서의 역사 기록 `분할 없음·1패스 = 82.6%` 는 BASE#1 과 정확히 일치했다.

## 4. 채점기가 오답을 통과시킨다

R 검토에서 제기됐고 **합성 입력으로 전부 재현했다.** 하나는 검토에 없던 것이다.

정답 `음료A / ICE / 우유량 / 225ml` 에 대해:

| 카드 내용 | 판정 | 실제 문제 |
|---|---|---|
| `ICE 음료A 우유 225ml` | COVERED | (정답) |
| `음료A HOT 우유 225ml, ICE 우유 275ml` | **COVERED** | 규격과 값이 뒤바뀜 |
| `ICE 음료A 우유 225g` | **COVERED** | 단위가 다름 |
| `ICE 음료A 우유 225ml는 잘못된 값이고 275ml를 넣는다` | **COVERED** | 정답 값을 명시적으로 부정 |
| `ICE 음료A 우유는 넣지 않는다 225ml` | **COVERED** | 금지인데 지시로 통과 |

현재 규칙은 대상·값·규격을 각각 확인하지만 **셋이 올바른 관계로 묶였는지**는 보지 않는다.
낱말과 숫자가 같은 카드 안에 있다는 것과 올바른 사실 관계가 표현된 것은 다르다.

`COVERED` 는 "정답을 맞혔다" 가 아니라 **"그 카드에 글자가 다 들어 있다"** 는 뜻이다.
(불변식 6 — 숫자·낱말 검사는 의미 정확성을 보장하지 않는다)

### 규격 채점의 별도 문제

규격 축이 없는 대상(한 규격만 존재)에 규격 표기를 요구해 부당하게 감점했다.
실행당 3~7건이고 **승격 문턱 5건과 같은 자릿수**다.

대상 단위 축 판정을 도입해 보정하니 A 매장 손실이 평균 79.4% → 77.0% 로 내려가고
폭이 5.3 → 4.5%p 로 좁아졌다. **다만 흔들림은 한 건도 줄지 않았다** (64→64, 16→16).
흔들림은 규격 채점 탓이 아니라 카드 내용 자체가 실행마다 달라지는 추출 변동이다.

대상 단위 축만으로는 부족하다는 후속 지적이 있다 — 같은 대상이라도 사실마다 적용
범위가 다르다. [W1_MEASUREMENT_PLAN.md](../plan/W1_MEASUREMENT_PLAN.md) ② 참조.

## 5. W1 구조 변경 이후 측정 (판정 보류)

파이프라인을 `입력 → 사실 → 원장 → 조립 → 카드` 로 바꾼 뒤 B 매장 3+3 회.

| 군 | 손실 | 카드 |
|---|---|---|
| W1 | 27.1 · 27.1 · 25.0 % | 56~65장 |
| W1-AA | 22.9 · 27.1 · 20.8 % | 56~58장 |
| (기준선) | 25.0 ~ 41.7 % | 29~41장 |

`loss_stage`: EXTRACTION 10~13 · ASSEMBLY 0~2 · CARD_ONLY 1~8. 원장 99건 전부 LINKED.

**이 수치로 개선을 주장하지 않는다.** 이유는 넷이다.

1. 위 4절의 오통과가 고쳐지지 않았다.
2. `match_fact` 는 모든 카드 중 최고 판정을 집는다. W1 은 카드를 기준선의 1.5~3배로
   만들므로 **우연히 글자가 겹칠 기회가 단조 증가**한다. 손실 감소분 중 얼마가 실제
   개선이고 얼마가 이 부작용인지 현재 도구로 가를 수 없다.
3. 기준선과 W1 을 같은 채점기로 재평가하지 않았다.
4. `ASSEMBLY` 가 작다는 것을 "조립이 잘한다" 로 읽으면 안 된다. 참조 연결 누락이나
   채점기 오류를 배제하기 전에는 위치 추정일 뿐이다.

관찰로만 기록할 만한 것: **변동 폭이 16.7%p → 6.3%p 로 줄었다.** 손실 수치보다
이쪽이 더 의미 있을 수 있으나, 같은 채점기 재평가 전에는 확정하지 않는다.

## 6. 사람 검토 비용

"자동 확정할 수 없으면 보류" 로 바꾸면 자동 판정이 멈추는지 재봤다.

```
카드 31장 · 정답 48건
  COVERED 판정      22건
  자동 확정 불가      1건  (5%)
```

278건 전체로 늘려도 **6~10건** 규모다. 자동 판정이 멈추지 않는다.

첫 측정에서 82% 가 나왔으나 그것은 탐지기 결함이었다 — 정상 카드의 여러 숫자를
"혼재" 로 잡고 단위를 `ml입니` 로 잘랐다. 고친 뒤의 값이 위 수치다.
탐지기가 잡는 것은 **생각해 본 패턴뿐**이므로 5% 는 하한이다.
