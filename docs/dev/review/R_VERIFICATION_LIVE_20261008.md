## 확인한 잔여 문제

1. **상황별 결론이 없다.** 환불 대화의 세 답변은 같은 환불 RAW 전체다. 정정 질문에서 관련 근거를 반환하는 경로는 개선됐지만, 실제로 날짜·결제수단을 바꾸고 금액을 유지해 결론을 냈는지는 이 출력만으로 증명되지 않는다. 기존 엄격한 완결 기준을 유지해 ANSWER 5건을 `INCOMPLETE_ANSWER`로 잠정 분류했다.
2. **필수 근거 누락을 모델 검증기가 통과시킬 수 있다.** OD06-1은 A 결제 확인/B 환불 승인 대기를 각각 적어야 하는 질문인데 인수인계 일반 규정만 선택했다. 원결제 상태 확인 P02는 검색 후보에 있었지만 최종 선택에는 없다. 인용 자체가 정확하다는 것과 답변이 충분하다는 것은 다르다.
3. **사건 선택 질문이 지원되지 않는다.** OD06-2의 “그 건은 메시지 읽었대”에 검증기는 A/B 중 대상이 불명확하다며 `MISSING_USER_INFO`와 구체적인 설명을 반환했다. 하지만 현재 계약은 entity/temperature/size만 지원하므로 최종 ESCALATE였다. 허위 답변 차단은 작동했지만, 사용자에게 A/B를 물으면 해결할 수 있는 상황이므로 목표 행동 기준에서는 `INAPPROPRIATE_ESCALATION`으로 잠정 분류했다.
4. **5초 목표 미달이다.** 관측된 제안·검증 호출 양쪽이 주요 시간을 차지한다. 이번 6턴만으로 안정된 지연 분포나 장기 비용을 추정하지 않는다.

따라서 엄격한 완결 답변 0/6·완결 시나리오 0/3은 이번 소수 질문에 대한 보조자의 잠정 판정이다. “Gemini의 일반 정확도 0%”가 아니다. 모델 독립 사람 평가·운영 인수도 아니다. 필요한 재질문은 여전히 적절한 대응으로 인정하지만 이번 출력에는 없었다.

## 다음 구현 순서

- 사용자 발화에서 사건 A/B의 표시명과 근거 턴을 보존하는 명확화 계약, 같은 세션에서 선택→후속 질문 연결. 매장 정책 entity와 개별 거래 사건을 분리하고, 추정 값을 확정 슬롯으로 승격하지 않는다.
- 승인 규정의 적용 조건·예외와 사용자 상황을 연결하는 답변 계획·통제된 결론 렌더링. 원문 나열만으로 해결 여부를 판정하지 않는다. RAW 조건의 정형화·승인 범위가 필요한 부분은 W 계약과 함께 다룬다.
- 선택 결과의 필수 근거 누락 회귀와 단계별 지연 개선 후 같은 소수 문항 재검증. 이후 24턴 전체·반복 평가를 진행한다.
