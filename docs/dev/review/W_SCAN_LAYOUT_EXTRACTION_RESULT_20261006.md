## 발견

1. **세로 병합 칸이 손실의 주원인이었다.** 띠로 자르면 합쳐진 칸의 조각만 보인다. 표 구역마다 판단 모델 1회로 병합 묶음을 받아 행에 채우고 규격을 코드로 정규화하자(Task 10) 47.7% → 87.9%.
2. **Haiku 는 지금 프롬프트로 띠 전사에 쓸 수 없다.** 같은 표에서 행마다 칸 수가 10·11·12로 흔들려 머리글과 맞지 않았다.
3. **판단 모델을 키운다고 좋아지지 않았다.** Opus 는 머리글을 12열로 잡았고(실제 11열), 일관되게 11칸을 낸 Flash 전사와 어긋나 표가 문단 경로로 넘어갔다. → **설계 약점:** 전사 결과가 행끼리 일관돼도 판단 모델의 머리글 열 수와 하나만 다르면 표 전체가 재경로된다. 후속 과제.
4. **카드 조립은 이 규모를 처리하지 못한다.** 사실 1,537건 중 92건만 카드에 실렸다(run 95). W3(사실 참조 조립)에서 다룬다.
5. **제품 버그 수정:** 추출·조립 Gemini 호출에 요청 시간 제한이 없어 응답 없는 연결에 45분 묶였다. `gemini_request_timeout_sec`(기본 300초) 추가.
6. **일시적 네트워크 끊김에 약하다.** 영수증 DB 저장이 한 번 실패하면 구역 전체를 버린다. 재시도(DB 기록, 구역 단위)와 Anthropic 요청 시간 제한이 후속 과제.
7. 소요 시간 19~26분/자료(대부분 Gemini 사고 토큰). 구역 병렬화가 후속 과제.
