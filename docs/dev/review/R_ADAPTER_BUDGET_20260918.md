# 검토된 의미 제안 제품 연결과 평가 예산 강제

## 구현 범위

`reviewed_semantics.py`는 검토된 모델 제안을 기존 v2 저장 경로에 연결한다. 질문·사용자 문맥·확정 슬롯·매장·승인 snapshot·검색 후보가 검토 입력과 정확히 같아야 한다. 사람의 별도 applicability 판정으로 서버 assessment를 만들고 기존 참조/조건/예외/RAW 검증과 저장 직전 현재 발행판·권한 검사를 모두 거친다. 답변은 승인 자료 renderer로 생성한다. 모델 슬롯을 확정하거나 질문을 자동 병합하지 않는다.

이는 **등록된 해석의 제품 연결 완료** 범위다. 처음 보는 모든 자유 표현을 실시간 모델로 판단하는 일반화 경로의 품질 인수 완료가 아니다. 검토되지 않은 표현은 기존 planner 결과를 유지한다. ANSWER·CLARIFY·정책 응답은 덮어쓰지 않는다. 검토 artifact 오류는 503이며 질문을 점주에게 잘못 넘기는 것으로 숨기지 않는다.

기본 `R_REVIEWED_SEMANTICS_ENABLED=false`. 활성화에는 private catalog 경로와 별도로 고정한 hash가 필요하다. catalog에는 acceptance_reference, 각 항목의 reviewer/review_reference, 제안 및 별도 interpretation이 필요하다. 이 필드는 사람 검토 사실을 자동 증명하는 전자서명이 아니며 배포 담당자가 실제 검토·인수 증거와 대조해야 한다. 요청이나 모델은 catalog를 설치할 수 없다. 파일을 매 요청 다시 읽으므로 플래그 OFF/승인 artifact 교체로 철회한다. 실제 catalog는 만들거나 활성화하지 않았다.

## 예산 계약

`run_r_semantic_evaluation.py`의 live 의미 제안 호출은 승인 `--budget-policy`, `--budget-hash`를 필수로 받는다. 정책은 campaign UUID, 매장/run 목록, 모델, 만료시각, 최대 호출 수/금액/입출력 토큰/입력 bytes, KRW 단가 상한과 근거·승인자를 명시한다. 기본 예산·실제 단가를 임의로 정하지 않는다.

공급자 접근 전에 PostgreSQL 행 잠금으로 최대 입력+출력 비용 및 호출 1회를 예약한다. 같은 캠페인의 여러 프로세스/run에 한도가 공유되며 중복 call key, 정책 변경, 만료·다른 매장·종료 run을 거절한다. 실패·재시도·크래시·적게 사용한 호출도 환불하지 않는다. 입력 schema까지 포함한 실제 prompt를 count_tokens로 검사하고 출력 max_output_tokens를 전달한다. SDK 자동 재시도는 1회다. 관측 토큰이 없거나 한도를 넘으면 캠페인을 정지한다. 새로운 캠페인 ID를 발급하는 것은 새로운 승인 예산이며 자동 재개 수단이 아니다.

금액 강제의 전제는 승인 단가가 환율·가격 구간·부대비용을 포함하는 상한이고 공급자가 토큰 한도를 지키는 것이다. 공급자의 초과 청구를 이미 발생한 뒤 취소할 수는 없다. token count 요청은 생성 호출 횟수와 별개이며 생성 전 요청 1회가 추가된다. RESERVED 상태는 실행 중 또는 크래시 후 미확정일 수 있고 비용 0으로 처리하지 않는다.

**현재 예산 어댑터 범위는 이 의미 제안 생성 runner다.** embedding/reranker를 포함한 전체 HTTP 품질 평가의 통합 예산이라고 해석하지 않는다. 그런 유료 캠페인을 실행하려면 단계별 가격·토큰 제한·예약 어댑터와 총예산 배분을 먼저 확정해야 한다. 이번 실행은 모든 공급자를 합성 대체했고 유료 호출은 없다.

## 검증과 재개

- 단위/계약: catalog 일치·불일치·변조·기본 OFF, RAW 누락 및 자동 병합 거절, 예산·scope·입력 토큰·출력 제한.
- 격리 DB verifier: 병렬 8개 중 2개만 예약, 재시작/정책 변경/중복 거절, 금액 독립 제한, 결측·초과 정지, 정산 멱등성, 브라우저 역할 권한.
- HTTP verifier: 실제 검색 결과를 대상으로 합성 catalog만 설치하고 기존 저장/인용/재요청/감사 metadata/오류 시 저장 차단 확인. 이 합성 검토는 매장 정답을 대신하지 않는다.
- 로컬 실행: 전체 802 tests, 4 xfailed, 119 subtests 통과. 계약 schema 15개/fixture 3개 최신. PG17 전체 migration 29개(현재 작업 폴더의 별도 W migration 포함)와 DB/API 회귀 통과, v2 HTTP 112 checks. 커밋에 포함되는 R 변경만의 CI 결과는 별도로 확인한다.

RD-01 사람 정답과 RD-02 유료 평가는 계속 대기다. 실제 W snapshot/worker 공동 인수도 별도다. 새로운 일반화 모델을 무검토로 활성화하지 않는다.
