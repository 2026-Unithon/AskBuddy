# R 상황 적용 결론과 필수 근거 검사 — 2026-10-08

## 문제와 변경

10월 8일 실제 Gemini 진단에서는 환불 조건을 정정해도 같은 승인 원문만 표시됐고, 인계 답변에서 검색 후보에 있던 선행 결제 확인 근거가 빠져도 검증기가 통과시켰다. 이전 결과를 다시 채점하거나 성공으로 고치지 않고, 이 두 실패를 다룰 출력·검증 계약을 추가했다.

| 항목 | 이번 동작 |
|---|---|
| 상황 적용 | 명시적 `grounded_conclusion` release에서 ANSWER 결론 1~8개를 요구한다. 기본 `approved_original`은 기존 원문 출력이다. |
| 결론 근거 | 현재 질문의 정확한 인용, 순서가 고정된 사용자 발화 인용, 선택한 승인 사실/RAW 참조를 연결한다. 버전·발화·선택 참조를 벗어나면 차단한다. |
| 후보 전체 검사 | 검증기가 모든 검색 후보를 단일 사실/RAW 단위로 필요/불필요 및 이유와 함께 분류한다. 누락·중복·외부 참조는 오류다. |
| 필수 근거 누락 | 검증기가 supported=true를 반환해도 required=true 근거가 선택 답변에서 빠지면 `GENERAL_VERIFICATION_REJECTED / INCOMPLETE_ANSWER`로 차단한다. |
| 표시 | 현재 질문에 대한 안내 → 결론과 출처 번호 → 승인 근거 원문. 기존 인용 상세 조회를 사용한다. |
| 출력 한도 | 제목·결론·원문·계산식 전체에 기존 ChatResponse의 2,000자 한도를 적용한다. 원문을 자동 삭제·잘라내지 않고 저장 전에 검증한다. |
| 저장 | `GROUNDED_LLM/VERIFIED`, 결론과 사용자 근거, 검증 기록을 보존한다. 동일 요청은 저장된 답변을 재전송하며 모델을 다시 호출하지 않는다. |
| 오류 | 검증 실패는 답변 receipt나 점주 대기를 만들지 않는다. 실제 지식 부족 이관과 구분한다. |

`VERIFIED`는 서버 구조 검사와 별도 모델 검증을 통과했다는 내부 분류다. 사람 확인 정답, 외부 결제/승인/인계 실행 완료, 추론의 수학적 증명을 의미하지 않는다. 결론은 공개 fact나 사용자 확정 슬롯이 되지 않는다. 두 번의 모델 호출 구조를 유지하며 자동 재시도·세 번째 교정 호출을 추가하지 않았다.

## 검증

합성 모델 응답으로 다음을 검사했다. 이는 실제 Gemini 정확도 측정이 아니다.

- 결론→출처 번호→원문 표시, 미검증 결론 차단, 기본 release에서 결론 차단.
- 사용자 인용·턴·현재 질문·카드 버전·선택 참조 위조 차단, 이전 상태/정정 인용의 정확한 순서 보존.
- 결론 검토 누락/중복, 후보 검사 누락/중복/외부 참조, 필수 참조 누락 차단.
- 지원된 결론도 전체 출력 한도를 넘으면 원문을 잘라내지 않고 오류 처리.
- 실제 FastAPI·PostgreSQL 저장/인용 상세/재전송, `GROUNDED_LLM/VERIFIED`와 근거 보존, 누락 시 receipt·pending 없음.
- 기존 A/B 선택·고정 문맥·다른 세션/임의/오래된 선택 차단과 R/W 공개·삭제·검색·인용 회귀.

## 확인하지 못한 것과 다음 평가

서버는 모델이 필수라고 분류한 근거의 누락을 확실히 막지만, **실제로 필요한 근거를 모델이 잘못 불필요로 분류하는 오류는 결정론적으로 발견하지 못한다.** 참조와 인용이 맞아도 결론의 의미가 틀릴 수 있다. 검색 자체가 놓친 자료도 후보 전체 검사로 복구되지 않는다.

다음 실제 평가에서는 기존 고정 질문에 대해 다음을 확인한다.

1. 환불의 최초 조건 → 정정 → 금액 유지에서 결론이 해당 사건의 바뀐 조건에만 반응하는지.
2. 결제 확인·인계 등 여러 근거를 조합할 때 선행 근거와 실행 순서가 빠지지 않는지.
3. A/B가 모호할 때 필요한 선택만 묻고, 선택 후 다른 사건 상태를 섞지 않고 답하는지. 적절한 명확화는 실패가 아니다.
4. 결론별 출처와 승인 상태, 인용 상세, 오류/이관/재질문, 미완성 응답을 전체 시도 분모에 남기는지.
5. 늘어난 검증 출력의 토큰·비용·잘림·지연을 실제 측정하는지. 기존 5초 기준은 아직 충족했다고 볼 수 없다.

새 버전·snapshot·출력 모드·질문·호출 수·비용 상한을 고정한 소수 진단부터 시작하고, 이후 24턴과 반복 평가로 확장한다. 이전에 소진된 호출 예약을 재사용하거나 상한을 자동으로 늘리지 않는다. W 실제 조립 출력·운영 실자료에 대한 통합 인수는 별도로 남는다.
