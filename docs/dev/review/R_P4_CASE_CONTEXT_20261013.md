# P4 사건별 답변과 문맥 — 2026-10-13

P4의 로컬 구현·회귀 검증이다. 실제 모델 품질·운영 p95 인수, 유료 호출, 배포는 수행하지 않았다. 과거 RAW 캠페인의 점수를 새 사실 카드 결과와 비교하지 않는다.

## 바뀐 동작

- 일반 의미 계약 v12의 `case_requirements`가 질문에 필요한 사건과 현재 상태를 결론 작성 전에 명시한다. 정확한 사용자 발화·순서로 결속하고, 독립 검증 결과가 일반 양식으로 축소하거나 A/B 중 하나를 빠뜨리면 저장 전에 거절한다. 사건 선택 뒤에는 선택한 한 사건만 허용한다. 일반 양식·무관한 새 주제는 이유가 있는 NOT_APPLICABLE을 유지한다.
- 상태 원문과 결론 표현을 분리했다. 사용자 원문 `메시지 읽었대`는 정확히 보존하되, 결론의 `메시지를 읽었다는`은 `state_unit_id`로 해당 문장에 연결할 수 있다. 같은 결론에 속하고 문장 검증이 GROUNDED_CASE_FACTS이며 동일한 사용자 출처를 포함해야 한다. 다른 사건·문장·미확인 상태·원문 없는 인용은 허용하지 않는다.
- 사건명과 실제 다음 행동 인용, 후보 전체의 필수 근거, 선택 규칙의 결론 적용, 미확인 사실 단정 검사를 유지한다. 읽음 상태가 추가돼도 미확인 결제의 다음 조치가 사라지지 않도록 제안/검증 지시를 보완했다.
- 일반 의미 경로에서 사용자 확정 대상과 분할 카드 제목을 비교하던 부분을 승인 snapshot의 대상 이름으로 바꿨다. 대상 선택지도 entity마다 대표 대상명 하나를 사용하며, 다른 대상 문맥은 계속 거절한다.
- `source_hash`에 대상 이름 모듈도 포함했다. 새 계약은 새로운 hash에 결속된 release가 필요하다. 공개 HTTP 응답·DB migration·과거 receipt·제품 플래그·timeout은 변경하지 않았다.

서버는 참조·출처·검토 범위를 검사한다. 사건/최신 상태 열거의 완전성, 제안과 검증기의 동일한 오판, 다음 행동의 의미 정확성 자체는 합성 통과로 입증되지 않는다.

## 과거 실패의 보존

`api/tests/fixtures/r_p4_state_expression_live_20261008.json`은 10월 8일 마지막 선택 요청의 실제 제안·검증·요청을 변경 없이 보존한다. 기존 상태 문자열 검사에서 누락으로 판정되던 것을 재현한다. 별도 합성 v12 문장 검토를 덧붙이면 바꿔 쓴 상태 표현의 출처 연결이 통과함을 확인했다. 이는 과거 답변 전체를 정답으로 재판정한 것이 아니다. 당시 빠졌던 결제 확인 조치는 별도 새 사실 HTTP fixture에서 확인한다.

## 검증 범위

`verify_r_p4_case_context.py`는 P3 러너의 실제 W 원장·조립·공개를 사용한다. 외부 추출/임베딩/제안/검증만 합성이다. 유료 SDK 생성은 실패하도록 막았다. 인계/결제/환불 정책 사실은 별도 매장에서 공개하며, 분할 문맥은 또 다른 매장에 실제 W 분할 조립으로 만든다.

| 경로 | 확인한 동작 |
|---|---|
| A 결제 미확인 / B 환불 승인 대기 | 각각의 구체적 다음 조치와 승인 사실 인용 |
| “그 건은 메시지 읽었대” | 원문 A/B 선택, 서버 context/revision 발급 |
| 실제 A 선택 | 읽음 표현 변경과 미해결 결제 확인 조치를 함께 보존 |
| 동일 요청 재전송 / 오래된 선택 | 새 생성 없이 receipt 재생 / 422 차단 |
| A 상태 정정 후 검증 실패 | receipt·pending 생성 없이 실패 사용자 발화 보존 |
| 다음 요청 복구 | 실패한 정정을 사용자 근거로 사용하고 B 상태 유지 |
| 새 일반 양식 질문 | 과거 사건을 강제로 적용하지 않음 |
| 질문 범위 축소 / 미확인 상태 | 각각 검증 거절, receipt·pending 생성 없음 |
| 타 매장 토큰 | 대화 이력·인용 직접 조회 404 |
| 실제 W 분할 카드 | 대상→온도 2회 선택 뒤 일반 의미 사실 답변·저장·OWNER_TEXT 인용 |

단계별 search/save 시간은 실제 함수 호출을 계측한다. proposal/verification은 서버 감사의 값을 사용하고, 재생된 receipt의 과거 모델 시간을 새 호출 시간으로 세지 않는다. 모델·임베딩이 합성이므로 이 시간을 운영 p95 또는 실제 모델 응답 속도로 해석하지 않는다. 실패 요청의 저장되지 않은 모델 단계 시간은 미측정이며 0으로 채우지 않는다.

전체 migration 재구축 검증은 별도 UUID DB에서 W/R 기존 흐름, 401/403/404/422, 카카오 인증, 과거 인용, 초기화·재등록을 실행했다. 임시 DB는 각 러너가 삭제한다.
