모델 호출 내역(로그):
- 텍스트 레이어 0자 → 문서 전체를 첨부로 넘김(HYBRID 의 스캔본 분기)
- 추출 1회: 입력 2,831 token, 출력 933 token, 사고 2,350 token, 16.8초, `finish` 정상(잘림 아님)
- 조립 1회: 사실 10건 → 카드 8장

## 해석

1. **잘림이 아니라 요약이다.** 출력 한도에 닿지 않았다. 모델이 표 한 장의 수백 칸 중 대표 몇 개(가격)만 골라 냈다.
   외부 앱 Gemini 실행(14~36건)과 같은 양상이고, 출력이 잘리지 않아(finish 정상) 잘림 분할 재추출 플래그의 발동 조건 자체가 없었다. 플래그를 켠 실행은 이번에 하지 않았다.
2. **입력 해상도가 의심된다.** 3쪽 표 이미지의 입력이 2,831 token 이다. 작은 글씨의 칸 안 수치를 읽기에 부족할 수 있다.
   외부 실행에서 값이 수렴한 것은 모두 띠 단위로 잘라 2배 이상 확대한 경우였다.
3. **조립은 원인이 아니다.** 사실 10건이 모두 카드에 실렸다(버림 0). 손실은 전부 추출 단계에서 났다.
4. 이전 실행의 eval-a 원장(25건, 참조 대비 3.3%)도 조건 기록은 없으나 같은 규모였다.

## 권고

계획의 분기 기준(참조 대비 80% 미만)에 해당한다. **SCAN 다단계 추출을 W3 보다 먼저** 한다.
카드 조립(W3)을 고쳐도 원장이 10건이면 카드 품질의 상한이 그 10건이다.

다단계 추출 설계의 출발점(외부 실행 관찰 근거):
- 쪽 이미지를 원본 해상도로 꺼내 띠 단위로 잘라 확대 입력
- 모델은 칸 원문을 행 단위로 **전사만** 하고, 사실 전개는 코드가 한다(출력 폭발 방지)
- 행 번호 연속·열 누락·띠 겹침 불일치를 코드로 검사하고 의심 칸만 재확인 호출
- 효과 측정은 이 참조와 `compare_reference.py` 로 같은 조건에서 비교한다
