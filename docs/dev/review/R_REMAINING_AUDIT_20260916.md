# R 잔여 계획 대조 감사

2026-09-16. 로컬 작업 트리의 전체 계획과 구현을 대조한 기록이다. 새 기능 구현·테스트 재실행·Docker 실행·pull·push는 하지 않았다. 미커밋 구현도 현재 코드로 포함했다.

기준: `ASKBUDDY_MVP_CURRENT.md` §30~31, `C0_DECISIONS_AND_PLAN.md`, `DEV_TODO_CURRENT.md` R0~R5/J0~J3, `plan/R_IMPLEMENTATION_PLAN.md`와 후속 review. 과거 review는 수정하지 않는다.

## 결론

R 전체 완료도, Docker/W 없이 가능한 작업 전체 완료도 아니다. 기반 계약·검색·저장·평가 도구는 많이 구현됐지만 일반 의미 판단, 제품 루프의 v2 연결, 운영 정책과 평가 연결의 잔여가 있다. 체크박스가 비어 있다는 이유로 이미 구현한 기능을 다시 만들면 안 된다. 반대로 단위 테스트 통과를 실자료 품질이나 실제 W 연결 완료로 해석하면 안 된다.

## 실자료·사람 검토와 평가 잔여

| 번호 | 남은 항목 | 필요한 입력/완료 조건 |
|---|---|---|
| B01 | 질문 정답·적용 범위 확정 | 실자료 자체는 확보. R 질문, 기대 행동 5종, 필수 사실/RAW, 금지 주장, 조건/예외, SPECIFIC/COMMON/NOT_APPLICABLE/UNDETERMINED를 근거와 함께 검토. W 사실 정답을 그대로 R 질문 정답으로 전환하지 않음 |
| B02 | 실제 승인 snapshot 매핑 | 실제 승인판에 stable meaning ID→fact revision 또는 RAW 참조 매핑. 합성 snapshot으로 대체하여 실제 성능 주장 금지 |
| B03 | 질문 커버리지 확충 | 현재 준비된 대표 질문 초안은 2매장 각 20개. 계획은 실제 snapshot별 30~50문항 이상이므로 총 40개만으로 충족하지 않음. 검토 전 초안도 확정 정답 수로 세지 않음 |
| B04 | 검색 관련성/pooling 평가 | vector·lexical·oracle 합집합과 미검색 표본 검토, 모집단 audit, recall@k/MRR/nDCG/완전 근거 회수율. 도구는 구현됨 |
| B05 | 사전/hybrid/reranker 독립 효과 | 같은 고정 자료로 단독·조합 비교, 후보 수/cutoff 튜닝은 dev에서. reranker 실제 모델 품질·비용·지연 확인 전 기본 ON 금지 |
| B06 | 의미·인용·행동/대화/묶음 평가 | 오답과 단순 무인용, 과차단, 적절한 CLARIFY/이관, 대화 완료, 잘못 합침/불필요한 분리를 별도 분모로 보고. 미판정을 자동 정답/오답으로 메우지 않음 |
| B07 | 채점기 사람 대조 | 기계 판정 표본 검토로 오류 유형·신뢰 범위를 확인. 표본 비율을 모든 후속 실행에 고정 보정값으로 적용하지 않음. 채점기/자료 분포 변경 시 재점검 |
| B08 | 반복/비교/비용 승격 | baseline/W-only/R-only/W+R, 최소 3회와 A/A, 고정 hash·분모·가격·환율, p50/p95/오류율·전체 원가·Storage 시나리오. 비용 미관측은 UNKNOWN. holdout은 사전 등록 후 별도 캠페인 |

질문 초안 생성·커버리지 표 설계는 R 단독으로 가능하다. 매장 사실의 진위 확정이나 실제 승인 snapshot을 R이 임의 작성하여 입력 부족을 해소하면 안 된다.

## Docker/실제 W·공동 인수 잔여

| 번호 | 남은 항목 | R의 역할 |
|---|---|---|
| C01 | 최신 변경 DB/API/UI 회귀 | 최신 조건/예외/RAW/grouping 변경을 실제 DB 저장·재시도·권한·TTL·공개 변경과 연결해 재검증. 이전 DB 성공 결과를 최신 변경 성공으로 재사용하지 않음 |
| C02 | PrepareIndex→W 원자 발행 | 실제 W producer와 schema/hash/revision/권한/잠금 접점을 대조. 중복·역순·누락·실패 복구와 색인 준비 재시도/폐기 책임 인수 |
| C03 | OWNER_ANSWER→ApplyOwnerAnswer | NEW/IDENTICAL/SUPPLEMENT/CONFLICT, 실제 worker 재시작/lease/fencing/중복/실패, 발행 성공 후 FAQ·학습·검색까지 확인. W 지식 반영기를 R이 중복 구현하지 않음 |
| C04 | legacy/이관/롤백 | 기존 카드 RAW 어댑터, 과거 인용·v1 세션 안전성, 신규 snapshot과의 호환, migration/이관 누락 수, flag/index 롤백. W 소유 이관과 공동 검증 분리 |
| C05 | 제품 종단 | 점주 1명·직원 2명의 질문→이관→점주 원문→발행→알림→재질문. 교차 매장/권한 회수/승인 제외·삭제 원본 인용 상태 포함 |
| C06 | 공동 품질 인수 | W가 R 권한/조건 보존 검토, R이 W 원장/승인/충돌 검토. 실제 자료에서 W 손실과 R 검색·판정·저장 손실 분리 |

실제 배포, 기기 Push/PWA, 네트워크·브라우저 사용감, 운영 환경 알림·백업 인수는 release 작업과 연결한다. FAQ/worker의 미구현 서버 정합성을 release로 옮겨 dev 완료 처리하지 않는다.

## 구현된 기반: 다시 만들지 않을 것

- JWT 매장 격리·rate limit·deadline, 승인 snapshot/hash/참조 검증, 원자 저장·stale 제한 재검색.
- M2 staging/활성화 접점, lexical/vector/RRF, 승인 사전, 선택형 reranker 및 usage 기록.
- 5행동/서버 렌더/인용, v2 context TTL·멱등성, 정책 확인, occurrence/점주 원문 전달·앱 내 알림·내보내기 접근 감사.
- 합성 E0, v2 단일/다회 평가 수집, 반복 캠페인 gate, pooling/모집단/근거 recall/oracle, 검토 자료 수입·의미 묶음 평가 도구.

위 목록은 기반 구현 확인이다. 지원 범위 전체·실자료 성능·W 종단 완료 선언이 아니다.
