# R 복합 질문·후속 대화 보완 — 2026-10-06

## 문제와 변경

기본 planner는 단일 대상·속성 중심이며, 자유 후속 질문에 DB의 이전 사용자 발화를 전달하지 않았다. 일반 의미 경로도 ESCALATE만 재검토하여 복합 질문에 생긴 일반 entity CLARIFY가 그대로 남았다.

- 일반 의미 경로에서 ANSWER 항목 2~8개를 각각 검증하고 합친다. 각 항목의 조건/예외/의존성/출처와 전체 참조 집합을 다시 검사한다. 일부 항목만 답한 결과를 구조적으로 합치지 못하게 한다. 의미상 질문 전체를 빠짐없이 해석했는지는 별도 검토가 필요하다.
- 같은 매장·회원·세션의 최근 원문 10개를 순서대로 전달한다. 검색은 현재 질문과 최근 원문 3개를 사용한다. 과거 모델 답변·평가 정답/expected_context를 주입하지 않는다. 대상별 정정과 주제 전환은 프롬프트와 의미 검토가 담당하며 결정론적 이해를 보장하지 않는다.
- 모델 처리 중 다른 답변이 저장되면 저장 트랜잭션에서 `STALE_DIALOGUE`를 반환한다. 이전 요청 재전송은 기존 receipt를 반환한다. 공개 지식 변경 검사는 그대로 유지한다.
- 선택된 typed 수량의 합/차 및 원문 양의 정수 개수 곱을 서버가 Decimal로 계산한다. 환산은 ml/l, g/kg, 분/시간 안에서만 가능하며 원·개도 지원한다. 예: 승인 포장재 120원 + 승인 봉투 30원 → `계산: 120원 + 30원 = 150원`. 이는 합성 구조 테스트 예시다.
- 선택 밖 숫자, 단위 혼합, 출처 없는 개수, 부정 사실, 범위 초과를 차단한다. 승인 원문·조건·예외·인용을 보존하고 계산식만 추가한다. RAW 조건부 가격·할인율·시간 계산은 지원하지 않는다.

## 활성화와 범위

일반 의미 경로 기본 OFF, 승인 설정의 매장/snapshot/소스/model/만료 검증, 두 단계 모델 제안/검토, 호출·비용·시간 제한을 유지한다. 소스 hash가 바뀌었으므로 기존 승인 파일의 hash만 바꾸어 승격해서는 안 된다. 새 평가와 승인 설정이 필요하다. W3 연결 전에도 RAW 다중 참조는 사용할 수 있으나 typed 계산은 승인 quantity가 필요하다.

공개 AnswerPlan v1, ChatResponse, W snapshot과 DB schema는 변경하지 않았다. 내부 resolved_query에는 항목별 참조 및 계산식을 추가한다. 이 변경 자체는 새 매장 정책이나 자유 생성 설명을 허용하지 않는다.

## 검증 기록

- Python 전체: 1605 passed, 4 xfailed, 131 subtests passed.
- 매장 격리 AST: 변경 폴더 위반 0건.
- 신규 회귀: 두 대상의 참조 합집합, 조건/예외 누락, 다른 질문/매장/버전/후보, 계산 방향/소수/단위/개수, 원문 순서와 조회 범위, 대화 경합 차단, 일반 CLARIFY 의미 경로 진입.
- DB 검증 스크립트에 실제 세션 이력 조회, 다른 매장/회원/세션 404, 새 질문 경합, 실패 receipt 롤백, 재전송 및 실제 HTTP의 과거 원문 전달 검사를 추가했다.
- 로컬 Docker 엔진 파이프가 없어 API·DB 검증은 로컬 실행 불가. 기존 CI의 일회용 PostgreSQL 검증 결과는 후속 기록으로 남긴다.

이 문서는 모델 정확도 보고서가 아니다. 기존 운영 질문 진단은 24발화를 독립 입력한 기본 경로 측정이며, 새 일반 의미 경로의 실제 모델·세션 정확도나 개선율을 나타내지 않는다. 모델 제안 모의 응답은 배선·구조 테스트에만 사용했다. 실제 품질·비용·p95와 W3 종단 검증은 미완료다.
