# R 정책 명시 확인·직원 앱 알림 검증

2026-09-16. W 변경 없이 진행한 R4/R5 후속 항목이다. 이전 기반은 `R_RUNTIME_IMPLEMENTATION_20260916.md`, 재정렬 계측은 `R_RERANK_USAGE_20260916.md`를 따른다. R 전체 완료 기록은 아니다.

## 구현과 계획 대조

MVP §31-5의 SAFE_ROUTE는 자동 문의를 만들지 않고 별도 확인 요청 때 ESCALATE가 된다. 이를 다음과 같이 연결했다.

- 기존 `POST /learn/v2/chat`에 선택 필드 `policy_receipt_id`를 추가했다. 저장된 SAFE_ROUTE의 매장·회원·세션과 원문을 검사한다. REFUSE, 다른 질문, 명확화 선택의 동시 제출은 거절한다. 일반 요청의 기존 body hash는 유지한다.
- 모델 호출 없이 명시 요청을 ESCALATE로 저장한다. 원문과 원래 정책 receipt ID를 보존한다. pending·occurrence·앱 알림·답변 receipt는 기존 단일 transaction에 들어간다.
- 세션 잠금 후 정책 참조를 재검사한다. 동일 요청 키 재시도는 원래 응답을 재생하며 서로 다른 키의 동시 요청은 하나만 성공하고 나머지는 409다. 다른 매장/회원/세션은 404다. 정책 안내 자체에는 문의가 없다.
- 직원 v2 대화의 최신 SAFE_ROUTE에 명시 확인 버튼을 제공한다. 서버 이력의 원문을 사용하고 실패 재시도에는 같은 요청 키를 쓴다. 요청 중 버튼을 비활성화하고 작성 중인 다른 질문은 지우지 않는다. 이전 안내에서 새 질문으로 대화를 진행한 경우에는 이전 안내의 버튼을 표시하지 않는다.
- `/staff/notifications/v2`에 직원 앱 알림 목록·커서 페이지 조회·읽음 처리·대화 이동을 연결했다. 서버 Query를 정본으로 사용하고 성공 후 해당 알림/대화 캐시를 무효화한다. 읽음 저장 실패 시 성공 표시나 이동을 하지 않는다. 외부 주소 등 임의 destination을 router에 넘기지 않는다.

MVP의 기존 목표 경로 표기는 `/learn/chat/v2`이고 현재 구현은 `/learn/v2/chat`이다. 이번에는 기존 R v2 경로를 확장했으며 경로 변경이나 v1 전환을 하지 않았다. 가산 request/history 필드를 정본에 명시했다. 안전 안내의 문구·정책 분류 기준, 답변 충분성 승인, W 발행 계약은 변경하지 않았다. 새 migration은 없다.

브라우저는 정책 확인 새로고침 복원·실패 재시도·진행 중 버튼 제한·작성 입력 보존과, 알림의 빈 상태·조회 오류·읽음 실패·정확한 대화 이동·읽음 복원·페이지 조회·임의 주소 차단을 확인했다. `api/tmp/r-ui/policy.png`, `notifications.png`와 결과 JSON을 생성하고 화면을 시각 확인했다. 해당 산출물은 Git 제외 경로다. 저장소의 과거 `UI/` 목업 경로는 존재하지 않아 기존 v2 화면 구성과 현재 모바일 규격을 기준으로 검토했다.

중간 실패도 수정 후 재실행했다. 추가 DB fixture의 잘못된 stores 컬럼명을 실제 스키마에 맞췄다. 브라우저 검사는 Next의 route announcer를 실제 오류로 오인하지 않게 구체적인 오류 문구를 기다리고, 이동 완료 후 새로고침하며, mutation 렌더 이후 버튼 상태를 확인하도록 수정했다. 마지막 DB/API 및 브라우저 실행은 모두 exit 0이다. 의도적으로 주입한 알림 저장 RuntimeError 로그는 rollback 검증의 예상 결과다.

DB는 일회용 로컬 Docker이고 정리했다. 프런트 검증용 서버도 종료했다. 유료 모델 호출·운영 DB·배포·커밋·푸시는 실행하지 않았다. 브라우저의 API는 합성이므로 실제 DB와 브라우저가 연결된 전체 E2E라고 부르지 않는다.
