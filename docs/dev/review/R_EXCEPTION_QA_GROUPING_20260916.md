# Docker/W 없이 진행한 R 의미 경계 확장

2026-09-16. 사용자 요청에 따라 Docker 실행, DB 변경, W 구현, 외부 모델 호출을 제외했다. planner `r-explicit-slots/v5`, 새 의미키 `r-explicit-question/v2`다. 이전 검증 기록은 수정하지 않는다.

## 이번 구현

1. **예외**: 승인 예외가 `단체 주문 제외` 같은 명시 제외 절일 때, 질문이 `단체 주문이 아닌 경우`라고 적용 범위를 명시해야 통과한다. 필수 조건과 선행 사실 조건도 모두 필요하다. 원래 예외 문구는 답변에 남긴다. 예외 적용 여부 미확인, 실제 예외 상황, 이중 부정, 임의 대체 수량·일반 주의 문장은 승인으로 바꾸지 않는다.
2. **일반 RAW의 승인 질의응답 경로**: RAW 전부가 명시적인 `질문: ... / 답변: ...`이고 질문과 일치하는 경우 수량 이외 절차·서술 답변도 원문 전체로 제공한다. 단일 카드·단일 RAW·후보 내 참조만 허용하고 typed 사실, 다른 Q/A 쌍, 카드 규격 불일치나 질문 추가 조건이 있으면 이 경로로 승인하지 않는다. 정확한 Q/A를 임의 바꿔 말하기의 승인이란 뜻으로 쓰지 않는다.
3. **의미 묶음 확대**: 우유/물뿐 아니라 명시 위치·가격·개수 질문, 크기·조건·예외 범위를 키에 포함한다. 모든 선행 조건을 대조하고 순서만 다른 조건 conjunction은 같은 범위로 묶는다. 매장·공개 snapshot·규격·속성·조건·예외가 달라지면 키가 다르다. unresolved context나 모델 유사도만으로 묶지 않는다.
4. **저장 전 재검사 유지**: 새 의미 문맥은 기존 save_answer의 서버 재계산 검사에 연결된다. 키 버전이 달라 기존 명시 수량 v1 pending과 자동 합쳐지지 않는다. 기존 pending/receipt/occurrence는 수정하지 않는다. 자동 그룹 확대는 새 요청부터 적용한다.

## 검증

- 전체 **660 tests passed / 119 subtests passed**.
- 기존 Starlette/AnyIO deprecation warning 1건.
- 변경 app 파일 4개 매장 격리 AST 위반 0건.
- 예외 누락/활성/부정/복합 예외 거절, 조건 순서와 표현 차이의 동일 키, 다른 속성 묶음, 일반 Q/A RAW 원문 보존, 미승인 paraphrase/다중 Q/A 거절을 추가했다.
- Docker/DB 통합은 사용자 요청에 따라 실행하지 않았다. 앞선 Docker 실패를 이번 통과로 바꾸지 않는다.

## 완료 범위의 해석

| 범위 | 상태 |
|---|---|
| 명시 조건 conjunction, 제한된 제외 예외, 원자 RAW 수량·원문·승인 Q/A, 확정 슬롯별 의미 묶음 | 구현 및 단위 검증 |
| 자유 서술 RAW의 충분성, 임의 복합 논리/수치 예외, 문구가 다른 일반 의미 동치 | 여전히 미지원이며 추정 승인하지 않음 |
| 최신 DB 저장·동시성·HTTP 통합 | Docker 재개 후 검증 |
| 실제 승인 snapshot 교체/발행/OWNER_ANSWER 지식 반영 | W 공동 인수 |
| 의미 오답·과도한 차단·묶음 precision/recall | 사람 truth와 실제 승인 snapshot 기반 평가 필요 |

Docker/W 없이 R 코드 작업은 가능하지만, 이번 제한된 확장을 일반 의미 판단 전체 또는 모든 R 단독 작업의 종료로 표시할 수 없다. 특히 표현이 같은 승인 질의응답 처리와 자유 서술의 의미적 충분성 판단은 별개다. 이를 닫으려면 범용 의미 판단의 구현 및 독립 판정 사례를 추가해야 하며, 단순 문형 규칙을 계속 늘린 결과를 범용 모델 성능으로 보고하지 않는다. 기본 v2 rollout OFF와 기존 승인/격리 경계는 유지했다.
