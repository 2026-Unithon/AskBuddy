# W 측정 교정·임베딩 계측 검증

2026-09-15. 요청 범위: docs 검토 후 출력 채점 → detail 오류 → 연결 수명/EMBED 계측 → 문서에 맞는 반복 판정 순차 수정.
운영 DB 변경·유료 API·holdout 개봉·커밋·푸시는 하지 않았다.

## 구현

- 출력 MATCHED 전에 속성을 확인한다. 확인한 별칭만 허용하고 공통 단어는 값 일치로 세지 않는다. 숫자·단위·부정·조건 결합이 다르면 MATCHED가 아니다. 원장도 속성·전체 값을 확인한다.
- 카드의 단위 불일치·부정/정정·규격 교차·동일 단위 다른 값 혼재·속성 확인 불가는 UNDETERMINED. COVERED만 분자, 보류는 고정 분모에 남기고 별도 집계한다.
- 평가용 적용 범위 SPECIFIC/COMMON/NOT_APPLICABLE/UNKNOWN과 검사를 추가했다. 규격 축이 있는 미라벨 사실은 UNKNOWN이며 공통으로 추정하지 않는다. 제품 계약 확정·사람 라벨링의 대체물이 아니다.
- `compare_runs.py --detail`의 이름 오류를 제거하고 반복별 성공 Δ 중앙값으로 성능을 계산한다. 만장일치는 안정성 진단, 모든 반복의 필수 악화·성공→변동·미판정은 차단이다. A/A 폭은 전체 성공 개수 max−min, 문턱은 ceil(1.5w), 최소 5. 실패·분모 누락을 숨기지 않는다.
- R paired_gate도 must_have_ids를 주면 모든 짝에서 관측 악화를 직접 검사한다. 기존 외부 안전성 입력과 함께 적용한다. 산술 통과를 운영 승격으로 표시하지 않는다.
- W 카드 승인·수정·점주 답변 공개는 공급자 호출을 트랜잭션 전에 준비한다. 요청 ShortSession은 쿼리마다 연결을 반환하고 트랜잭션 동안만 고정한다. 저장할 때 잠금·승인·내용·버전/제안 상태를 확인해 충돌 시 롤백한다.
- `recorded_embeddings`와 DbUsageSink를 사용해 호출 1회에 receipt 1개. 원본 작업의 phase/purpose/source/job/campaign 귀속을 이어받고 귀속 불명 원본은 호출 전 보류한다. 점주 답변/수정은 OPERATING, 평가 목적은 원본 기록에서 유지한다. 여러 카드를 실제 batch 호출로 합치는 변경은 하지 않았다.
- 새 평가 리포트는 실행 당시 카드·원장·정답 입력을 보존한다. `rescore_extract_report.py`는 이 입력만 재채점하고 원본/기존 결과 덮어쓰기를 거절한다.

## 아직 미완료

BASE/BASE-AA·W1/W1-AA의 대상 리포트 **18개**를 확인했다. 모두 `results`에 예전 판정과 card_id만 저장하고 실행 당시 카드 본문·원장·정답 snapshot을 담지 않는다. DB source_facts에도 실행별 immutable 원장 key가 없다. 현재 DB 카드로 과거 실행을 재구성하거나 기존 COVERED를 새 점수로 재사용하지 않는다.

따라서 ④ 실제 재평가는 **입력 복구 대기**다. 원본 실행 snapshot이 외부에 있다면 새 재평가 도구로 복구할 수 있다. 이 작업은 새 유료 재추출을 승인하지 않는다. 실제 보류 6~10건·COVERED 무작위 10~15건의 독립 사람 검토도 남아 있다. 합성 반례 통과로 실제 데이터 오통과율 또는 W1 성능 개선을 주장하지 않는다.
