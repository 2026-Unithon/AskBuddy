# R0 승인 블록과 색인 모집단 대응 검사 — 2026-09-16

## 목적과 구현

검색 결과나 색인에 존재하는 문서만 평가 모집단으로 쓰면 색인 누락을 놓칠 수 있다. 승인 snapshot의 전체 `(card_id, card_version_id, block_id)`를 독립 기대 집합으로 만들고 준비된 색인의 전체 문서와 대조한다.

- `api/app/reg/index_audit.py`: snapshot hash 검증 후 누락·예상 밖 참조·중복 및 기대/실제 개수를 반환한다. 잘못된 버전은 기존 참조 누락과 예상 밖 참조로 함께 표시한다. 보고서 내용 지문을 포함한다.
- 평가용 `search_channels(include_universe=True)`는 동일 repeatable-read 트랜잭션에서 **현재 승인 필터 전의 전체 색인**을 대조한다. 불일치 시 `IndexUniverseMismatch.audit`에 진단을 제공하고 평가 수집을 중단한다. 실패를 성공 점수나 축소된 분모로 바꾸지 않는다.
- 대응이 완전하면 현재 승인/공개 버전 필터를 별도로 적용해 검색·표본 대상 참조를 만든다. 카드 제외는 현재 평가 대상에서 빠지지만 불변 snapshot 대응 검사의 기대 개수를 줄이지 않는다.
- 수집 결과에 `universe_audit`를 포함하고 새 검사 모듈의 소스 지문을 남긴다. 제품 `hybrid_search`의 기본 경로에는 전체 모집단 조회/검사가 추가되지 않는다.

계획의 R0 pooling/검색 평가를 위한 보완이며 W 계약·migration·공개 API를 변경하지 않았다. 전체 R0 완료가 아니다.

## 검증 결과

- `verify_r_handoff.ps1 -IncludeSchemaRebuild -IncludeUnitTests` 완료.
- **553 tests / 116 subtests** 통과. 기존 의존성 경고 1개.
- 신규 단위 7개: 정확한 대응/순서 독립, 누락, 잘못된 버전, 추가 블록, 중복, 빈 색인, 불완전 색인에서 수집 중단과 연결 해제.
- 일회용 PostgreSQL 17.11에서 **26 migration** 재구축. M2 **40**, reranker 13, 답변 저장 16, v2 API 84, 점주 전달 21, 선행 원가/보안/W/문맥 60 = **234 PASS 확인**. 반복 provider 검사를 포함하므로 독립 시나리오 수는 아니다.
- 실제 DB에서 cutoff와 독립된 전체 블록 개수 및 승인 제외 후에도 불변 대응 검사 분모 유지 확인. 손상 색인 반례는 순수 함수/모의 DB 응답으로 검증했으며 DB 불변성 트리거를 해제해 손상시키지는 않았다.
- 변경 모듈 3개 매장 격리 정적 검사 통과. 종료 시 일회용 DB/컨테이너 정리.

## 한계와 다음 작업

이번 검사는 **참조의 완전성**이다. 색인 텍스트/벡터의 의미 품질이나 질문별 정답 관련성까지 증명하지 않는다. 현재 승인 snapshot 밖의 원자료 누락은 W 원장/추출 평가 영역이다. 임베딩은 합성이므로 실제 검색 품질 향상 주장을 하지 않는다.

다음 R 단독 항목은 pool hash와 정확한 참조에 연결된 **별도 사람 관련성 판정 계약·수입**이다. 검토하지 않은 후보를 오답으로 처리하지 않고, 오래된 판정·중복·다른 pool 판정을 거절해야 한다. 그다음 안정적 사실 의미 ID와 승인판별 근거 매핑, 검색 지표/oracle 분해로 이어간다.
