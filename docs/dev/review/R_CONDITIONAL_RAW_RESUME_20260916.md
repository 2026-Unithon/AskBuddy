# R 재개: 명시 조건·RAW 수량 및 실자료 검토 표본

2026-09-16. 앞선 `R_SOLO_DEV_DATA_AND_GROUPING_20260916.md` 이후 기록. 기존 변경을 보존했다. C0의 승인 참조·조건 보존·미확정 규격 차단을 유지하며 planner를 `r-explicit-slots/v4`로 확장했다.

## 구현

- 승인 typed 사실과 선행 사실의 조건을 전부 질문 앞부분에 명시한 경우를 처리한다. 최대 4개 조건의 순서 변경과 `그리고` 연결을 지원한다. 조건은 승인 문구 전체와 대조하고 원문 그대로 출력한다. 이는 조건을 가정한 질문의 범위이며 실제 현장에서 조건을 이행했다는 판정이 아니다.
- 조건 일부 누락, 부정·다른 시점·`또는`, 미확인 예외, 다른 추가 요청을 통과시키지 않는다. 같은 규격의 경쟁 사실은 조건 문구만으로 상호 배타성을 가정하지 않고 충돌로 남긴다.
- 조건 판단 결과는 매장·snapshot hash·질문 hash·target revision과 선행 closure에 결속한다. 다회 문맥은 현재 단일 질문 assessment와 달라 별도 보류하며 저장 시 hash를 고쳐 우회하지 않는다.
- RAW는 승인된 단일 카드·단일 RAW 블록 전체가 명시 HOT/ICE·대상·우유/물·수치/단위 문장인 경우 일반 수량 질문에 응답한다. 원문·인용을 그대로 반환하며 역추출한 typed fact를 만들거나 승인하지 않는다.
- RAW에 추가 조건/예외/부정/다른 수량/지시문이 있거나, 후보 누락·다른 카드·typed 사실·규격 충돌이 있으면 이 경로를 사용하지 않는다. 제목이나 숫자 일부가 겹친다는 이유로 허용하지 않는다.
- 새 로직 파일도 단일/다회 평가 실행의 source hash에 포함한다.

일반 RAW 전체, 자유로운 복합 의미 해석이나 자연어 예외 추론을 완료한 것은 아니다. 제한된 의미 지원 범위를 넓힌 것이며 실제 질문에서의 과도한 차단과 오답률은 독립 검토가 필요하다.

## 실자료 작업

원본 hash에 묶인 기존 180건 dev 사실에서 평가 전 대표 질문 40개를 준비했다. 자료 유형을 먼저 순환하고 속성·규격 존재 여부별로 분산한다. 각 매장 20개이며 KAKAO/SCAN/VIDEO/VOICE가 각각 5개다. 실제 값·원문은 Git 제외 경로에만 남겼다.

- `api/eval/data/store-a/r-review/queue-611b50c095daf0d3.json`
- `api/eval/data/store-b/r-review/queue-a938925f0e8a6856.json`

위 파일은 최신 source-type-first 표본이다. 앞선 순서의 queue 파일은 덮어쓰지 않았다. 새 표본의 `judgments`에 질문 초안만 넣었고 expected_action, must_have, 적용 범위, conditions/exceptions, 근거 revision, reviewer/reason은 미검토로 남겼다. 수입 검증기가 이 초안을 완성된 사람 판정으로 받아들이지 않는 테스트도 추가했다. 선정된 질문을 확인한 뒤 앞선 검토 수입 도구의 형식에 따라 제출한다. 실제 승인 snapshot이 없으므로 근거 revision을 임의 발급하지 않았다.

이 40개는 확정된 성능평가 정답셋이 아니다. 사용자가 별도 DB/승인 snapshot/검토본의 존재를 알려주기 전까지 실자료 semantic_accuracy는 미측정이다. 사실 TEST 라벨을 점주 승인이나 질문 기대 행동으로 승격하지 않았다. 실제 DB나 holdout을 읽지 않았고 외부 모델에 자료를 보내지 않았다.
