# R 검증 거절 분기·대화 정정 회귀 보완

2026-10-06. 이전 소수 유료 진단에서 후속 정정 질문의 제안은 환불 RAW를 선택했으나 검증기가 `supported=false`만 반환했고, 최종 응답은 9개 업무 선택 재질문으로 돌아갔다. 이전 사용자 원문이 공급자에게 전달되지 않은 문제는 아니었다. 당시 거절의 정확한 의미상 이유는 기록되지 않아 확정할 수 없다.

## 이번 구현

- 검증 응답에 거절 분류, 설명, 필요한 선택형 명확화, 검토한 사용자 턴 목록을 추가했다. 공급자 schema에서는 이 필드들을 필수로 요청한다. 서버는 성공 판정과 거절 사유의 혼용, 설명 없는 분류, 빠지거나 중복된 턴을 거절한다.
- `MISSING_USER_INFO`는 검증기가 대상·속성을 별도로 수락한 경우에만 기존 대상/온도/크기 선택형 계약으로 연결한다. 서버가 승인 후보의 선택지·확정 슬롯·서버 context ID·2턴 제한을 다시 검사한다. 금액·결제수단·사건명 등 미지원 필드는 임의 선택지로 만들지 않고 `UNRESOLVED_CONTEXT`로 점주 전달한다.
- `MISSING_KNOWLEDGE`와 `UNSUPPORTED_OPERATION`은 서버 고정 사유 `INSUFFICIENT_KNOWLEDGE`로 점주 전달한다. 이 분류 역시 모델 판단이며 실제 분류 정확도 인수는 별도다.
- `CONTEXT_CONFLICT`, `INCOMPLETE_ANSWER`, `UNVERIFIABLE` 및 사유 없는 거절은 `503 GENERAL_VERIFICATION_REJECTED` 오류다. 거절된 답변이나 광범위한 업무 선택지를 저장하지 않고 pending/알림도 만들지 않는다. 클라이언트에는 분류와 검증 hash만 전달한다.
- 정상적으로 저장된 명확화/이관의 execution metadata에는 설명과 검증 hash를 보존한다. 오류에는 receipt가 없으므로 서버 로그에 코드/hash를 남긴다. 모델의 자유 설명·사용자 원문은 오류 응답이나 일반 로그에 복제하지 않는다. 실제 유료 진단에서는 기존 runner의 공급자 응답 기록으로 상세 설명을 확인해야 한다.
- 같은 사용자 원문에 요청 내 순서를 붙여 제안·검증 양쪽에 전달하고, 검증기가 마지막 정정까지 검토했는지 구조적으로 검사한다. 프롬프트에 같은 사건의 일부 정정, 유지한 조건, 서로 다른 주문, 주제 전환, 모호한 지칭의 구분을 명시했다. 이 목록은 검토했다는 모델의 주장이지 의미 이해의 증명이 아니다.
- 제안/검증 단계의 소요 시간 `proposal_ms`/`verification_ms`를 기록한다. 정상 경로의 공급자 호출 수는 기존 2회이며 자동 재시도나 세 번째 호출을 추가하지 않았다.

외부 AnswerPlan/DB/프론트 계약은 유지한다. 내부 일반 의미 버전은 v4이며 새 검증 모듈·프롬프트도 소스 hash에 포함한다. 기존 승인 설정은 다시 발급·인수해야 하며 운영 플래그는 기본 OFF다.

## 검증

- 전체 단위 테스트: **1,817 passed, 4 xfailed, 131 subtests passed**. 기존 Starlette 경고 1건. `api/tmp/r-verification-full-01.log`.
- 새 검증 분기 테스트 30개를 포함한 초기 집중 회귀 106개 통과. 단계 시간 계측 추가 후 관련 56개 재확인 통과.
- PostgreSQL 17 전체 migration 41개와 API/DB 통합 검사 통과. `api/tmp/r-verification-pg17-02.log`.
- 실제 HTTP/DB에서 검증 오류 3종의 무저장·무pending, 지식 부족 이관의 사유/시간 저장, 재전송 시 공급자 재호출과 pending 중복 방지를 확인했다. 모델 응답은 합성이다.
- 최초 통합 실행의 신규 검사는 통과했으나 뒤따르는 이력 검사가 누적 요청 100회 테스트 상한에 걸렸다. 통합 suite의 테스트용 회원 한도를 1,000으로 조정한 뒤 전체 재실행했다. 운영 한도는 변경하지 않았으며 별도 제한 경계 테스트도 유지한다.
- `git diff --check` 통과. 유료 공급자 호출 **0회**.

## 남은 범위와 다음 평가

이번 작업은 검증 거절을 질문 모호함으로 바꾸던 분기를 수정한 것이다. 실제 정정 질문이 정답으로 전환됐다는 결과는 아직 없다. 합성 대화 회귀는 원문 순서·호출 결속·거절 처리만 검증하며 Gemini 이해도 점수로 집계하지 않는다.

거래별 금액/날짜/결제수단을 구조화해 저장하고 정정 적용 이력을 관리하는 일반 사건 상태, 자유 입력으로 부족한 조건을 묻는 계약, 승인 규정으로부터 상황별 결론을 렌더링하는 계약은 남아 있다. 현재는 저장된 사용자 원문을 다시 해석하며 모델 추정 값을 `confirmed_slots`로 승격하지 않는다. 제안 단계의 `unresolved` 처리와 검증 이전 구조 오류도 이번 검증기 거절 분기와 구별한다.

다음 실제 소규모 평가에서는 동일 거래의 날짜/결제수단 정정과 금액 유지, 두 거래 중 한 거래만 정정, 새 주제, 모호한 지칭, 실제 정보 부족을 포함한다. 정답, 필요한 재질문, 불필요한 재질문, 검증 오류, 점주 전달을 분리하고 기존 실패를 분모에서 제외하지 않는다. 새 schema의 공급자 호환성·토큰/비용·단계 시간도 함께 관측한다. 이 소규모 평가가 안정된 뒤 기존 24턴 전체를 재평가한다.
