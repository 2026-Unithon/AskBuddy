# SCAN 레이아웃 — 쪽·구역·전개 묶음 병렬화 실측 (2026-10-07)

> 브랜치 `w/layout-parallel`. 앞 기록: `W_SCAN_LAYOUT_MODEL_COMPARE_20261007.md`(3.6 + 사고 `LOW` 를 기본 후보로).
> 재현율은 다수결 참조 대비 **원장 기준**. 1회 실행이라 변동 판단은 하지 않는다.

## 바꾼 것

- 모든 쪽의 구역 지도를 동시에 부르고, 구역은 지도가 나오는 대로 처리한다. 자료 하나 안의 동시 구역 수는 `layout_region_concurrency`(기본 3).
- 표 전개 묶음(10행)을 표마다 `layout_concurrency` 안에서 동시에 부른다.
- 결과(사실·미해결·실패 구역)는 쪽 → 구역 순서로 합쳐 직렬과 같다.
- 금액 상한은 공용 멈춤 표시로 아직 시작하지 않은 쪽·구역을 실패로 남기고, 진행 중 작업이 끝나길 기다린다. 유료 호출 차단은 기존 `check_before_call`(모델 상한 안)이 보장한다.
- 띠 호출 상한은 검사와 동시에 예약(차감)한다 — 병렬 구역이 같은 순간 통과해 중간에 막히는 경합을 없앴다.
- 형제 작업이 여러 개 실패하면 취소 > 금액 상한 > 기타 순으로 올리고, 모든 형제가 끝난 뒤 올린다.
- 모델 호출 수는 기존 프로세스 상한(`ingest_model_concurrency`=4)이 그대로 묶는다.

검증: 단위 테스트 1,796 통과(병렬 전용 16건 — 동시 진행, 순서, 상한, 예약 경합, 직렬 동일성, 취소 우선). 매장 격리 검사 위반 없음. 독립 리뷰 Approved(외부 취소 시 하위 작업 정리를 탐침으로 확인).

## 해석

1. **추출 단계는 목표대로 줄었다(약 15분 → 4.5분).** 모델 호출 상한 슬롯이 놀던 것이 병렬로 채워졌다.
2. **이제 병목은 카드 조립이다.** 200건 묶음 9개를 차례로 불러 9분이 걸린다. 조립은 W3 에서 사실 참조 방식으로 바뀌므로, 조립 병렬화는 W3 쪽에서 다룬다.
3. **처음으로 종단 완료했다.** 카드 101장 저장, 원장 사실 1,567건이 모두 카드에 실렸다(Codex 의 조립 묶음 분할 효과).
4. 재현율 89.9% 는 직렬 `LOW` 두 번(91.8·92.2%)보다 약 2%p 낮다. 1회라 변동인지 병렬 영향인지 가르지 않는다. 병렬은 추출 입력·프롬프트·순서를 바꾸지 않으며(직렬 동일성 테스트), 전사 행이 104/101 로 3행 많아 겹침 행 중복 가능성이 있다 — 반복 시 확인한다.
