# R 사건별 다음 조치·평가 선택지 매칭 보완 — 2026-10-08

직전 실제 Gemini 평가에서 인계 질문은 공통 기록 항목만 답하고 A의 결제 확인/B의 승인 확인을 적용하지 못했다. 검증기도 선택하지 않은 결제 규칙을 불필요하다고 판단해 통과시켰다. 다음 턴에는 설명형 A/B 선택지가 나왔지만 러너가 정확한 `A`만 찾았으므로 마지막 선택은 미실행이었다. 이번에는 두 문제를 보완하고 **유료 모델 호출 없이** 회귀·API/DB 검증을 수행했다.

## 변경

- 일반 의미 **v9**. 제안 프롬프트는 사용자가 사건명·상태를 제시하고 다음 행동/인계를 물으면 사건별 이름·현재 상태·실제 다음 조치를 결론에 연결하도록 요구한다. 이름과 상태는 짧은 사용자 원문 인용, 조치는 승인 근거 참조로 구분한다. 공통 필드 목록만으로 사건별 적용을 대신하지 않는다.
- 검증의 `case_action_review`는 질문에 사건별 적용이 필요한지 독립 판단하고, 필요하면 각 사건명/상태의 사용자 발화 번호·정확한 인용과 적용 결론 번호·다음 행동 인용을 반환한다. 서버는 중복 사건, 원문에 없는 상태, 잘못된 턴/결론, 결론에서 빠진 사건명·상태·행동, 결론의 사용자 근거 불일치를 검사한다. 검증기가 `supported=true`여도 표시된 적용 누락은 `INCOMPLETE_ANSWER`로 거절한다.
- 해당하지 않는 일반 질문에는 `NOT_APPLICABLE`과 이유, 빈 사건 목록을 요구한다. `grounded_conclusion` 답변에 새 검토를 누락하면 계약 오류다. 기본 원문 모드와 비답변의 새 필드는 null일 수 있다. 공개 AnswerPlan/ChatResponse와 DB schema는 변경하지 않았다.
- 평가 질문의 `select_option_aliases`에 사전 지정한 표현을 허용한다. 실제 API의 case 선택지와 정확히 **하나**만 일치할 때 반환된 문자열과 실제 context_id/revision을 전송한다. 앞부분 비교·유사도·순서 추측은 하지 않으며 모호하거나 일치하지 않으면 미실행으로 남긴다. 별칭 형식은 API 대조군/유료 호출 전에 검사하고 실행 기록에 매칭 근거를 보존한다.
- 보고서의 일반 미실행 사유를 “선택지 자체가 없음”에서 “사전 문자열과 실제 선택지가 유일하게 일치하지 않음”으로 정정했다. 과거 원시 실행이나 발행된 HTML은 다시 쓰지 않았다.

**검증의 한계:** 사건 목록을 빠짐없이 만들었는지, 최신 정정을 맞게 선택했는지, 적용 불필요 판단과 다음 행동의 의미가 맞는지는 여전히 모델 판단이다. 필드와 정확한 인용이 존재한다고 의미 정확성이 증명되지는 않는다. 새 프롬프트/계약이 실제 Gemini에서 안정적으로 작동하는지는 후속 실측이 필요하다. 검증 오류를 자동 재생성하거나 점주 대기로 바꾸지 않으며 기존 비용·중복 요청 가드를 유지한다.

로그: `api/tmp/r-case-actions-full-02.log`, `api/tmp/r-case-actions-pg17-01.log`. 신규 사건/선택지 회귀 26개를 추가했다. 초기 실제 출력 재생은 planner 추정 슬롯을 확정 문맥으로 전달한 테스트 설정 때문에 실패했다. 실제 API와 동일한 빈 확정 슬롯으로 수정해 새 사건 검사까지 도달시켰으며 런타임 검사 우회는 없었다.

DB 검증의 공급자 응답은 합성이다. 실제 Gemini 새 성공 결과로 주장하지 않는다. 직전 일반 인계 출력을 그대로 보존한 `api/tests/fixtures/r_case_actions_live_20261008.json`과 수정된 합성 검토/기대 응답도 구분했다. 임시 검증 DB는 삭제됐고 PostgreSQL 서버는 종료했다. 운영 DB·플래그 변경 없음. 이 변경의 새 migration은 없지만 이전 실패 문맥 복구 migration 선행 배포 조건은 유지한다.
