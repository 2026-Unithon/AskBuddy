# 채점기 v4 — 공통/업종 규칙 분리와 속성 관계 교정

2026-09-28 · `w_fact_score/v4` · 규칙 묶음 `COMMON+CAFE`

## 왜

[9/27 사용자 판정](W_USER_DECISIONS_20260927.md)에서 사용자가 맞다고 확인한 카드 5건을 채점기가 떨어뜨렸다.
사람·AI 검토 68건을 기준표로 두고 재 보니 v3는 **틀린 것을 맞다고 한 건 0건, 맞는 것을 떨어뜨린 건 46건**이었다.
대부분 "대상·값은 있으나 속성 관계 미확인" 규칙이다. 정답지의 속성 이름(안전보관일, 청소주기, 발주요일 등)은
정답지를 쓴 사람이 붙인 라벨이라 카드 문장에 거의 나오지 않는데, v3는 그 이름을 글자 그대로 찾았다.

## 구조 — 공통 규칙 + 업종 규칙

`api/app/team/scoring_rules.py`

- **공통 규칙(COMMON)**: 어느 업종에나 항상 적용한다. 보관위치·처리주체·종료시각·소분·세척제·순서 같은 업무 표현과 기한·주기 별칭.
- **업종 규칙**: 공통 위에 덧붙인다. 지금은 카페(CAFE)만 있다 — HOT/ICE 동의어, 얼음 레시피의 ICE 표기 필수(9/16 사용자 확정),
  우유·온수·샷 같은 음료 속성 표현.
- 업종 규칙은 공통 규칙의 표현을 덮을 수 없다(`rules_for` 가 거절). 업종을 늘리면 `DOMAIN_EXTRAS` 에 묶음을 더한다.
- 평가 자료가 전부 카페라 기본은 `COMMON+CAFE` 다. 결과 파일에 `scoring_rules` 로 남긴다.

구조만 옮긴 단계에서 v3와 두 실행의 전체 사실 판정이 한 건도 다르지 않은 것을 확인한 뒤 교정을 넣었다.

## 교정 (모두 공통 규칙)

| 규칙 | 내용 | 막는 것 |
|---|---|---|
| 띄어쓰기 무시 | 속성 표현을 붙여서 비교("발주요일" ↔ "발주 요일") | — |
| 생략 주어 | 대상 문장 바로 뒤의 **숫자 없는** 문장까지 대상 범위로 본다 | 숫자 있는 뒤 문장은 다른 대상 값일 수 있어 넣지 않는다 |
| 값이 드러내는 속성 | 속성 표현이 정해지지 않은 속성은, 대상 문장 안에 값이 온전히 있으면 관계를 인정한다. 숫자는 **단위까지 붙어** 있어야 한다 | "3잔" ≠ "블렌더 3번". 표현이 정해진 속성("소분")은 계속 엄격 — "250g 소분" ≠ "250g 투입" |
| 활용 흔들림 | 값 낱말은 두 글자 이상이면 앞부분 일치로 본다("처리" ↔ "처리해야") | 부정·정정 검사는 그대로 |
| 순서 값 | "A → B → C" 는 항목이 같은 순서로 나오는지 본다 | 순서가 다르면 통과하지 않는다 |
| 규격 적용 범위 기본값 | 라벨이 없고 사실에 규격이 적혀 있으면 **그 규격 전용(SPECIFIC)**. 원본에 규격이 없어 레시피북을 따르는 사실만 사람이 COMMON 라벨을 붙인다 (2026-09-28 사용자 확정) | 규격 없이 쓴 카드는 불완전, 반대 규격 카드는 통과하지 않는다 |

부정·정정·예외, 같은 단위의 다른 값 혼재, 복수 규격, 적용 범위 미확인 보류는 바꾸지 않았다.
