## 구현과 범위

- 카드 후보를 대상/속성이 있는 문장으로 좁힌다. 다른 대상의 같은 숫자로 근거를 연결하지 않는다.
  같은 수준의 판정에서는 속성 관계가 있는 카드를 우선한다.
- 종료시각의 값 지정과 ‘영업 종료 전까지’ 같은 시간 참조를 가른다. 라스트오더 시각을 종료시각으로 쓰지 않는다.
- 정답지에 규격 축이 없더라도 명시적인 반대 규격은 통과시키지 않는다.
- ICE 정답 또는 확인된 얼음 레시피는 **ICE 문자열 표기**가 필요하다. 아이스라는 한글 표현만 있는
  기존 카드도 새 표시 기준으로는 불완전이다. 얼음 청소/보관/금지/없음은 얼음 레시피의 근거가 아니다.
- 문장 범위를 좁혀도 다른 문장의 부정/정정 신호는 보존한다. 관계가 확정되지 않으면 계속 보류한다.
- `expectation=ABSENT`와 `superseded_by`라는 **명시적 승인 라벨**로 이전 지시 제외를 검사한다.
  이전 값이 사라졌다는 이유만으로 성공하지 않고 최신 지시의 올바른 근거도 필요하다.
  이전 지시가 현재 카드에 남거나 최신 지시가 없으면 통과하지 않는다.
- 제외 검사는 일반 재현율 분모/성공 건수에서 분리한다. 모든 반복에서 제외 검사 실패/미판정이 있으면 안전성은 차단한다.
  비교 CLI는 옛/누락 채점 버전을 현재 판정으로 인수하지 않는다.

직접 카드 채점·추출 평가 runner·보존 리포트 재평가·반복 산술에 연결했다.
DB 스키마와 네 verdict 상태는 유지했다. ABSENT 행의 COVERED는 **제외 검사 성공**이지 옛 값을 카드에 담았다는 뜻이 아니다.
JSON 결과에 expectation/정정 연결을 남기고 별도 metrics로 보고한다.
원장은 과거 원본 사실을 보존하며 원장 출력 점수와 현재 카드 제외 검사를 구분한다.

dev 승인 라벨은 `api/eval/policies/w_user_confirmed_20260916.json`에 보존했다.
원본 snapshot의 대상/속성/값을 바꾸지 않고 별도 정책으로 재평가하며 정책 hash·채점 코드 hash를 남긴다.
