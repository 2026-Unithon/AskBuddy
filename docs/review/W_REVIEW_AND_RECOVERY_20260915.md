# W 후속 ① 표본 대조 · ② 과거 입력 복구 감사

2026-09-15 · 요청: 다음 W 작업 1번/2번 · **AI 근거 검토 완료, 사람 인수 미완료, 전체 과거 재평가 미완료**

## 결론과 담당

원본 찾기·표본 준비·카드 대조·복구 검사·재평가는 에이전트가 수행했다.
사용자가 이 작업을 처음부터 수작업으로 할 필요는 없다. 다만 AI의 판정을 독립적인
**사람 검수 완료**로 바꾸지는 않는다. 사실 단위 적용 범위·번복 기대 판정·영상 동작은
아래 확인 목록을 보고 확정해야 한다. 사용자가 보유한 별도 백업은 위치를 제공받아야 조사할 수 있다.

범위는 dev A/B뿐이다. 운영 DB 변경, 초기화, 유료 모델 재호출, holdout C/D 열람,
정답지/채점기 변경, 커밋/푸시는 하지 않았다. 원본과 개인정보성 내용은 Git 제외 경로에만 보존했다.

## ① 실제 표본과 검토 결과

`w_fact_score/v2`를 동결한 채 현재 로컬 보존 카드 A 26장/B 56장과 정답 A 132건/B 48건을 대조했다.
샘플링 seed는 `20260915`, 입력 hash는
`sha256:8e10629ce1e7b36db0a7f48548fb414be19a301d9e77b5f9c57d3f70733ee450`이다.
자동 `COVERED` 모집단이 **9건뿐**이어서 요청한 10~15건 대신 9건 전부를 검토했다.
자동 `UNDETERMINED`는 A 30/B 29, **59건 전부**를 검토했다. 합계 68건이고 검토 누락/중복은 없다.

PDF 원본 5개/10페이지를 렌더해서 육안 대조했고 카톡은 원본 텍스트를 확인했다.
음성은 보존 STT 전사문만 대조했다. 원본 청취 검증은 미완료이고 일부 정답지 timestamp도 실제 전사 시각과 다르다.
영상은 locator 정지화면·일부 연속 프레임·보존 전사문을 대조했으며 전체 동작을 보았다고 주장하지 않는다.
특히 A 영상의 보존 STT가 반복/깨진 문장으로 손상되어 순서·일괄 제조를 전사문만으로 확정할 수 없다.

무시해서는 안 된다는 후속 결함을 기록한다. 이번 표본에 맞춰 채점기를 수정하지 않았다.

1. **적용 범위:** a-0009/a-0010/a-0055의 ICE 생략을 허용할 근거가 있는가.

2. **번복 기대 판정:** a-0062/b-0044는 이전 지시를 현재 카드에서 제외하는 것이 의도다.
   원본의 과거 사실 재현과 최종 유효 지식 포함을 별개 평가로 확정해야 한다.

   b-0035의 약품 수량은 원본 영상 앞뒤/음성을 직접 확인해야 한다. 음성 근거 4건도 청취 인수는 별도다.

독립 사람 인수는 위 쟁점 확인만으로 자동 완료되지 않는다. 원래 검토 packet 전체의 사람 판정과
미검토 항목을 구분해 남겨야 하며, 확인 전 ② 라벨 확정·품질 승격을 보류한다.

## ② 과거 입력 복구와 재평가

Git/저장소 및 같은 로컬 작업 경로의 관련 snapshot/backup 이름을 점검했다.
해당 실험의 별도 보존 아카이브는 찾지 못했다. 다른 프로젝트 아카이브나 사용자 전체 홈은 조사하지 않았다.
기존 리포트는 판정 결과만 있고 실행별 `cards/ledger/truth/source_types` 입력 snapshot이 없다.
`reset_eval_store.py`가 카드·카드 버전·사실 원장을 함께 지우므로 이전 실행의 버전으로 돌아갈 수 없다.

대상 BASE/BASE-AA/W1/W1-AA는 **18개 유효 실행**이다. 별도로 발견된 0장 실행 2개는 기준선에서 제외했다.

| 범위 | 결과 | 새 채점기 counts (COVERED / 보류 / PARTIAL / MISSING) |
|---|---|---|
| A BASE-AA#3, run 78 | 보존 DB 입력의 조건부 복구·재평가 | 0 / 30 / 33 / 69 (132건) |
| B W1-AA#3, run 86 | 보존 DB 입력의 조건부 복구·재평가 | 9 / 29 / 10 / 0 (48건) |
| 나머지 16개 유효 실행 | 입력 미복구, 재평가 불가 | 판정 결과만으로 추정하지 않음 |

복구 후보는 report identity, 카드 수, 1번 불변 버전, 실행 구간 내 생성/수정 시각,
정답의 당시 리포트에 있던 6개 핵심 필드, 정정/번복 없는 원장, 카드/버전 내용,
DB·manifest·리포트 자료 hash, 실제 원본 파일 hash, 옛 verdict/선택 card ID 재생을 검사했다.
현재 입력 export와 복구 입력을 별도 파일로 남겼다.

**중요한 한계:** 이 두 개도 실행 당시에 동결한 snapshot은 아니다. 당시 코드는 `e43c0009482a-dirty`이고
dirty 변경의 정확한 상태는 복원하지 못했다. A는 기록된 base commit의 원래 정답/채점으로 재생됐다.
B는 base commit에서 b-0045 한 건이 달랐으며, 규격 축 로직이 들어 있는 **명시적인 호환 커밋 `aa49fa0`**에서
당시 verdict/선택 card ID가 전부 재생됐다. 그 호환 커밋을 원래 dirty 코드라고 주장하지 않는다.
최초 진단의 규격 생략 전처리가 A 재생을 다르게 만든 것도 확인하고, 최종 도구는 원본 truth를
변경하지 않은 채 커밋/runner의 규격 정책으로 재생하도록 했다. 최초 진단 파일은 삭제/덮어쓰지 않았다.

**전체 재평가 완료나 W1 개선을 주장할 수 없다.** 각 군의 3회 입력이 복구되지 않아 중앙값·안정성·
전체 반복 안전성 판정을 계산할 수 없다. 서로 다른 A/B의 counts를 성능 비교로 사용하지 않는다.
완료하려면 해당 16개 실행의 원래 입력 백업이 필요하다. 없으면 사전 고정된 새 실험을 별도로 승인받아야 하며,
이 요청으로 유료 재실행을 승인받은 것으로 해석하지 않았다.
