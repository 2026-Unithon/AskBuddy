# 화면 상태 실동작 확인

계약(MVP 정본 17-5)은 모든 화면이 아래를 **구분해서** 보여줄 것을 요구한다.

> 초기 로딩 · 빈 상태 · 오류 · 부분 성공 · 결과 없음 · 재시도 · 권한 없음 · 완료

"결과 없음" 과 "오류" 를 같은 빈 화면으로 보여주면 계약 위반이다. 사용자는 기다려야 할지
다시 눌러야 할지 모른다.

## 언제 쓰는가

- `web/` 화면을 추가하거나 고친 뒤
- 12.5-2 화면 상태 계약을 점검할 때
- "동작한다" 고 보고하기 전 — 정상 경로만 본 것은 확인이 아니다

---

## 준비

```bash
# DB
supabase start

# API
cd api && source .venv/bin/activate && uvicorn app.main:app --reload --port 8000

# WEB
cd web && pnpm dev     # http://localhost:3000
```

기준 뷰포트는 **390×844**, 보조 **360×800**, 콘텐츠 최대 폭 480px.
데스크탑 창으로만 보고 끝내지 않는다. 모바일 웹이 먼저다.

---

## 1. 정상 경로

화면을 열고 데이터가 보이는 것까지 확인한다. 여기서 끝내면 안 된다.

---

## 2. 초기 로딩

DevTools → Network → throttling 을 `Slow 3G` 로 놓고 새로고침한다.

- [ ] skeleton 이 뜬다. 흰 화면이나 그냥 "로딩중..." 텍스트가 아니다
- [ ] skeleton 의 구조가 실제 콘텐츠 구조와 같다 (뜨고 나서 레이아웃이 튀지 않는다)

---

## 3. 빈 상태 vs 결과 없음 vs 오류

셋을 각각 만들어 보고 **화면이 서로 다른지** 확인한다.

| 상태 | 만드는 법 | 기대 |
|---|---|---|
| 빈 상태 | 데이터가 아직 없는 신규 매장으로 진입 | 다음에 뭘 하면 되는지 안내가 있다 |
| 결과 없음 | 검색·필터로 0건 만들기 | "조건에 맞는 것이 없다" 는 뜻이 전달된다 |
| 오류 | API 를 끄고 새로고침 | 오류라는 것이 보이고 **재시도 버튼이 있다** |

```bash
# 오류 상태 만들기 — API 만 내린다
pkill -f "uvicorn app.main:app"
```

- [ ] 셋의 화면이 서로 다르다
- [ ] 오류 화면에서 재시도를 누르면 (API 를 다시 켠 뒤) 복구된다
- [ ] 오류가 빈 배열로 조용히 바뀌지 않는다

---

## 4. 백그라운드 갱신

이미 데이터가 보이는 상태에서 갱신이 돌 때를 본다.

- [ ] 갱신 중에 기존 콘텐츠가 사라지지 않는다
- [ ] 스크롤 위치가 튀지 않는다
- [ ] 갱신 중임을 알 수 있는 표시가 있다 (콘텐츠를 지우는 방식이 아니어야 한다)

---

## 5. 장기 작업과 이동·복원

업로드처럼 오래 걸리는 작업에서 확인한다. **12.5 의 핵심 항목이다.**

- [ ] 접수 직후 다른 화면으로 갈 수 있다
- [ ] 다른 화면에 갔다 돌아오면 진행 상태가 복원된다
- [ ] 처리 중 **새로고침(F5)** 해도 진행 상태가 복원된다
- [ ] 다른 화면에 있는 동안 완료되면, 돌아왔을 때 완료가 보인다
- [ ] 현재 화면에서 완료되면 **수동 새로고침 없이** 결과가 나타난다
- [ ] 뒤로가기로 돌아와도 깨지지 않는다
- [ ] 탭을 벗어났다 돌아오면(포커스 복귀) 상태가 다시 맞춰진다

---

## 6. 중복·경합

- [ ] 제출 버튼을 **연타**해도 작업·카드·알림이 하나만 생긴다
- [ ] 느린 이전 요청의 응답이 최신 결과를 덮어쓰지 않는다
  (필터를 빠르게 A→B 로 바꾸고 A 의 결과가 나중에 도착해도 B 가 유지되는지)
- [ ] 오프라인 → 재연결 시 자동으로 다시 조회한다 (DevTools → Network → Offline)

---

## 7. 실패 보존

- [ ] 제출 실패 시 입력한 내용이 날아가지 않는다
- [ ] 오류 메시지가 사용자 말로 쓰여 있다 (스택트레이스·영문 코드 노출 금지)

---

## 8. 레이아웃

390×844 와 360×800 에서:

- [ ] 잘리는 텍스트가 없다
- [ ] 하단 CTA 가 다른 요소에 가리지 않는다
- [ ] 터치 대상이 44×44px 이상, 본문이 16px 이상
- [ ] 가로 스크롤이 생기지 않는다

---

## 9. 테스트 후크

이후 E2E(13.6)가 이 화면에 붙는다. 지금 남겨두지 않으면 그때 다시 만져야 한다.

- [ ] 주요 조작·목록·상태 표시에 안정적인 `data-testid` 가 있다
- [ ] 폼 입력과 아이콘 버튼에 접근성 이름이 있다

---

## 보고 규칙

확인하지 않은 항목을 통과로 적지 않는다. 브라우저를 못 띄웠으면
"브라우저 확인 못 함" 이라고 쓴다. 정상 경로만 봤으면 그렇게 쓴다.

## 자동화 참고

브라우저 조작 자동화가 필요하면 공식 마켓플레이스의 `playwright` 플러그인을 검토한다.
정식 E2E 스위트는 13.6 단계 범위이고, 이 스킬은 그 전까지의 수동 확인 절차다.
